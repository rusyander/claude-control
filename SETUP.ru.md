## Требования

|                     | Минимум          | Проверить          | Примечание                                                                                       |
| ------------------- | ---------------- | ------------------ | ------------------------------------------------------------------------------------------------ |
| **Node.js**         | **22.6**         | `node --version`   | Ниже сервер не стартует вовсе — [почему](#сервер-падает-с-bad-option---experimental-strip-types) |
| **pnpm**            | 10               | `pnpm --version`   | `npm install -g pnpm`                                                                            |
| **Claude Code CLI** | любая актуальная | `claude --version` | Должен быть в `PATH` и залогинен                                                                 |
| **Git**             | любой            | `git --version`    | Нужен только для маркетплейсов плагинов                                                          |

В проекте лежит `.nvmrc`, поэтому `nvm use` подберёт нужную версию Node сам.

Claude Code должен быть именно **залогинен**, а не просто установлен: запустите `claude` один раз в терминале и пройдите аутентификацию. Панель не умеет логинить и не сделает это за вас — без этого часть возможностей (чат, помощник, разговоры в песочнице, плагины) просто не работает.

## Установка

```bash
git clone <адрес-репозитория>
cd claude-control
pnpm install
```

Отдельно и только если собираетесь запускать браузерные QA-скрипты:

```bash
pnpm qa:setup     # скачает сборку Chromium для Playwright
```

## Где искать папку `.claude`

Это та самая папка, которую правит Claude Control. Понимание, где она лежит, снимает большинство вопросов.

<table>
<tr><th>Система</th><th>Путь</th><th>Открыть командой</th></tr>
<tr><td><b>Windows</b></td><td><code>C:\Users\&lt;вы&gt;\.claude</code></td><td><code>explorer %USERPROFILE%\.claude</code></td></tr>
<tr><td><b>macOS</b></td><td><code>/Users/&lt;вы&gt;/.claude</code></td><td><code>open ~/.claude</code></td></tr>
<tr><td><b>Linux</b></td><td><code>/home/&lt;вы&gt;/.claude</code></td><td><code>xdg-open ~/.claude</code></td></tr>
</table>

Папка скрытая — из-за точки в начале. В проводнике включите **Вид → Скрытые элементы**, в Finder нажмите <kbd>⌘</kbd><kbd>⇧</kbd><kbd>.</kbd>.

Что должно быть внутри:

```
~/.claude/
├── CLAUDE.md              ваши правила
├── settings.json          хуки, права, переменные окружения
├── settings.local.json    личные хуки и права — панель показывает их с пометкой «локальные»
├── skills/                по папке на скилл
├── hooks/                 скрипты хуков
├── projects/              транскрипты разговоров
├── .credentials.json      вход — руками не трогать (на macOS его нет, см. ниже)
├── .mcp-secrets.env       токены MCP (необязательный)
└── claude-control/        создаётся этой панелью
    ├── state.json         группы, сценарии, настройки панели
    └── backups/           копии перед записью (последние десять на файл)

~/.claude.json             MCP-серверы и аккаунт — ВНИМАНИЕ: рядом с .claude, не внутри
```

> [!NOTE]
> То, что `~/.claude.json` лежит рядом с папкой, а не внутри неё, — особенность самого Claude Code, а не ошибка. MCP-серверы настраиваются именно там.

**Если конфигурация лежит в другом месте** — потому что вы задали `CLAUDE_CONFIG_DIR` или держите её на другом диске — панель найдёт её по этой переменной, а если нет, путь можно указать вручную в **Настройках → каталог конфигурации**. Выбор запоминается.

## Различия между системами

Панель написана так, чтобы вести себя одинаково везде: пути собираются средствами Node, каталог конфигурации ищется по `CLAUDE_CONFIG_DIR` и домашней папке, переводы строк не имеют значения. Разбираться руками приходится с немногим — и всё это собрано здесь.

**Проверить своё окружение одной командой:**

```bash
pnpm doctor
```

Скрипт ничего не меняет — он смотрит версию Node, наличие `claude` в `PATH`, каталог конфигурации, учётные данные, занятость портов и объясняет каждую находку. Запускается на всех трёх системах.

### Что различается на самом деле

| Что              | Windows                     | macOS                               | Linux               |
| ---------------- | --------------------------- | ----------------------------------- | ------------------- |
| Запуск CLI       | `claude.cmd` через оболочку | `claude`                            | `claude`            |
| Учётные данные   | `.credentials.json`         | **связка ключей**, файла обычно нет | `.credentials.json` |
| Список процессов | PowerShell                  | `ps`                                | `ps`                |
| Сравнение путей  | без учёта регистра          | с учётом регистра                   | с учётом регистра   |

Всё это панель делает сама. Вмешательство нужно в одном случае — на macOS с песочницей.

### macOS: песочница и связка ключей

**Симптом.** Все разделы работают, обычный чат отвечает, а песочница говорит «Not logged in».

**Причина.** На Windows и Linux Claude Code хранит токен файлом `~/.claude/.credentials.json`. На macOS он держит его в связке ключей, и файла в каталоге просто нет. Песочница собирает временный каталог и запускает Claude с `CLAUDE_CONFIG_DIR` — токен туда попасть не может.

**Что делает панель.** На macOS она читает токен из связки ключей сама (`security find-generic-password`). При первом обращении система один раз спросит разрешение — окно «node хочет получить доступ к ключу». Нажмите **Всегда разрешать**, и вопрос больше не появится.

**Если не помогло** — например, Anthropic переименовал запись в связке. Найдите её имя:

```bash
security dump-keychain | grep -i -A1 claude
```

Затем подставьте найденное имя переменной окружения и перезапустите панель:

```bash
export CLAUDE_CONTROL_KEYCHAIN_SERVICE="Claude Code-credentials"
pnpm dev
```

**Способ, который работает всегда: задать доступ вручную в панели.** Он не зависит ни от связки ключей, ни от того, где лежит файл, и перебивает автоматический источник — см. [Доступ вручную](#доступ-вручную).

**Способ в лоб, если связка ключей недоступна** (корпоративная политика, запуск по SSH). Токен можно положить файлом — Claude Code и панель прочитают его оттуда:

```bash
security find-generic-password -s "Claude Code-credentials" -w > ~/.claude/.credentials.json
chmod 600 ~/.claude/.credentials.json
```

Файл содержит JSON вида:

```json
{
  "claudeAiOauth": {
    "accessToken": "…",
    "refreshToken": "…",
    "expiresAt": 1784000000000,
    "scopes": ["user:inference"]
  }
}
```

> [!WARNING]
> Это настоящий токен доступа к вашему аккаунту. Права `600` обязательны, в репозиторий такой файл попадать не должен. Способ имеет смысл только там, где связка ключей действительно недоступна: сам Claude Code при истечении токена обновит запись в связке, а файл останется старым, и его придётся выгрузить заново.

### Доступ вручную

Запасной путь на любой системе, когда автоматический источник не находится или не подходит. Работает одинаково на Windows, macOS и Linux и **перебивает** автоматический — задают его как раз тогда, когда автоматический не работает.

> [!NOTE]
> Нужно это ровно одной вещи — **песочнице**. Чат, помощник форм, плагины и MCP запускают `claude` в вашем настоящем каталоге, и авторизацией там занимается сам CLI. Если песочницей вы не пользуетесь, ничего задавать не надо.

**По шагам:**

1. Откройте **Настройки** → карточка **«Доступ Claude Code»**. Значок рядом с названием показывает текущий источник: _файл настроек_, _связка ключей macOS_, _задан вручную_, _ключ API_ или _не найден_.
2. Нажмите **«Задать вручную»**.
3. Выберите образец — **Токен подписки**, **Ключ API** или **Свой файл** — и подставьте своё.
4. **Сохранить**. Ввод проверяется сразу: неверный JSON или отсутствие нужного поля покажут ошибку прямо в окне, а не потом отказом песочницы.
5. Значок сменится на **«задан вручную»**. Кнопка **«Убрать ручной»** возвращает автоматический источник.

**Три формы — любая на выбор:**

<table>
<tr><th>Когда</th><th>JSON</th></tr>
<tr><td>У вас есть <b>токен подписки</b> (то же, что в <code>.credentials.json</code>)</td><td>

```json
{
  "claudeAiOauth": {
    "accessToken": "sk-ant-oat01-…",
    "refreshToken": "sk-ant-ort01-…",
    "expiresAt": 1784000000000,
    "scopes": ["user:inference"]
  }
}
```

</td></tr>
<tr><td>У вас <b>ключ Anthropic API</b> — оплата пойдёт по тарифам API, а не по подписке</td><td>

```json
{ "apiKey": "sk-ant-api03-…" }
```

</td></tr>
<tr><td>Токен лежит <b>своим файлом</b> в нестандартном месте</td><td>

```json
{ "readFrom": "/полный/путь/к/credentials.json" }
```

</td></tr>
</table>

Обязательно только одно поле из трёх. Для `claudeAiOauth` минимум — непустой `accessToken`; остальные поля панель передаёт как есть.

**Что происходит с введённым.** Сохраняется в `~/.claude-control/credentials.json` с правами `600`. Обратно в браузер не отдаётся никогда: панель показывает только источник, но не сам токен. Тот же файл можно создать и руками, без интерфейса, — панель подхватит его при следующем обращении.

**Порядок источников** (первый найденный побеждает):

1. `~/.claude-control/credentials.json` — заданное вручную
2. `<конфиг>/.credentials.json` — файл системы (Windows, Linux)
3. связка ключей macOS
4. переменная окружения `ANTHROPIC_API_KEY`

### Linux

Особых шагов нет. Единственное, что стоит знать: файловая система различает регистр, поэтому путь к каталогу конфигурации должен совпадать с настоящим побуквенно — `~/.Claude` и `~/.claude` это разные папки.

Для QA-скриптов установка браузеров требует прав администратора:

```bash
sudo pnpm qa:setup
```

Самой панели браузеры не нужны — только прогонам из `tools/qa/`.

### Windows

Особых шагов нет. `claude.cmd` запускается через оболочку, аргументы с пробелами панель экранирует сама.

Если конфигурация лежит на другом диске, задайте путь переменной:

```powershell
$env:CLAUDE_CONFIG_DIR = "D:\claude-config"
pnpm dev
```

## Первый запуск

```bash
pnpm dev
```

Поднимутся обе половины сразу. Браузер откроется сам.

|            | Адрес                 |                                         |
| ---------- | --------------------- | --------------------------------------- |
| **Панель** | http://localhost:8888 | то, чем пользуетесь                     |
| **API**    | http://127.0.0.1:5178 | только локально, наружу не выставляется |

Запустить по отдельности — удобно, когда отлаживаете что-то одно:

```bash
cd apps/server && pnpm dev      # только API
cd apps/web && pnpm dev         # только фронтенд
```

Свои порты:

```bash
PORT=5200 API_PORT=5200 pnpm dev
```

> [!WARNING]
> Если меняете порт **фронтенда**, задайте серверу ещё и `WEB_PORT`: он принимает запросы только с origin своей панели, а неожиданный origin получит 403. Например: `WEB_PORT=9000 pnpm dev`.

При старте сервер печатает, где нашёл конфигурацию:

```
Claude Control API: http://127.0.0.1:5178
Каталог конфигурации: C:\Users\вы\.claude (источник: home)
```

`источник` говорит, какое правило сработало: `manual` (задано в панели), `env` (переменная `CLAUDE_CONFIG_DIR`), `home` (по умолчанию) или `not-found`.

## Как убедиться, что всё работает

Сначала — автоматическая проверка, она же первый шаг при любой проблеме:

```bash
pnpm doctor
```

Дальше быстрый обход по тем местам, где чаще всего оказывается что-то не настроено:

1. **Обзор** показывает ненулевые счётчики правил, скиллов и хуков. Нули везде — значит каталог не тот, смотрите строку `источник` выше.
2. **Правила** перечисляют разделы вашего `CLAUDE.md`.
3. **MCP** → _Проверить соединение_ у любого сервера возвращает список инструментов. Это проверка запуска процессов.
4. **Аналитика** показывает историю токенов. Это проверка чтения транскриптов.
5. **Чат** → отправьте «привет». Это сквозная проверка `claude` CLI и лучший короткий тест.

Если 1–2 работают, а 3–5 нет — панель в порядке, дело в `claude` CLI: начните с [раздела про CLI](#claude-не-найден--command-not-found).

## Починка

### Ничего не запускается

#### Сервер падает с `bad option: --experimental-strip-types`

Слишком старый Node. Сервер исполняет исходники TypeScript напрямую, для этого нужен **Node 22.6+**.

```bash
node --version        # если v20.x или v22.5 и ниже — причина в этом
nvm install 22 && nvm use 22
```

Без `nvm` поставьте актуальный Node с [nodejs.org](https://nodejs.org). После установки перезапустите терминал — в открытом остаётся старый `PATH`.

#### `EADDRINUSE: address already in use 127.0.0.1:5178`

Порт кем-то занят — почти всегда сервером из прошлого сеанса, который не остановили.

<details>
<summary><b>Windows</b></summary>

```powershell
Get-NetTCPConnection -LocalPort 5178 -State Listen |
  Select-Object -ExpandProperty OwningProcess |
  ForEach-Object { Get-Process -Id $_ }

Stop-Process -Id <pid> -Force
```

</details>

<details>
<summary><b>macOS / Linux</b></summary>

```bash
lsof -i :5178
kill -9 <pid>
```

</details>

Либо просто переехать: `PORT=5200 API_PORT=5200 pnpm dev`.

С портом фронтенда строже — включён `strictPort`, поэтому Vite не уползёт молча на 8889. Освобождайте 8888 тем же способом.

> Замечание: `node --watch` следит за дочерним процессом, и если убить именно дочерний, родитель остаётся в неопределённом состоянии. Если сервер перестал отвечать после падения — остановите его полностью и запустите заново, а не ждите, пока watcher сам разберётся.

#### `pnpm: command not found`

```bash
npm install -g pnpm
```

Заменять на `npm install` нельзя: это pnpm-workspace, и npm неправильно свяжет зависимость `packages/contracts`.

#### Установка падает из-за несоответствия lock-файла

```bash
rm -rf node_modules apps/*/node_modules packages/*/node_modules
pnpm install
```

Если не помогло, `pnpm install --no-frozen-lockfile` подберёт версии заново — ценой расхождения с зафиксированным lock-файлом.

### Панель открылась, но пустая или сломана

#### Во всех разделах нули

Панель читает не тот каталог — или каталог, который не является конфигурацией Claude Code.

1. Посмотрите строку запуска сервера или откройте **Настройки** — там показан найденный путь и его источник.
2. Убедитесь, что по этому пути действительно лежат `CLAUDE.md` и `settings.json` ([что должно быть внутри](#где-искать-папку-claude)).
3. Если путь неверный, задайте его в **Настройках → каталог конфигурации**. Некорректный путь не применяется, поэтому «увести» панель в никуда не получится.

Частая причина — забытая переменная `CLAUDE_CONFIG_DIR`, оставшаяся после экспериментов:

```bash
echo $CLAUDE_CONFIG_DIR          # macOS / Linux
echo $env:CLAUDE_CONFIG_DIR      # Windows PowerShell
```

#### `127.0.0.1:8888` не отвечает, а `localhost:8888` открывается

На системах, где `localhost` резолвится сначала в `::1`, dev-сервер, привязанный к `localhost`, поднимается только на IPv6 — и инструменты, ходящие по IPv4, до него не достучатся. В конфиге явно прописан `host: '127.0.0.1'`, чтобы этого не было. Если вы это убрали — верните в `apps/web/vite.config.ts` или пользуйтесь адресом `localhost` последовательно.

#### Запросы возвращают 403

API принимает только собственную панель как origin. Так бывает, когда фронтенд поднят на порту, которого сервер не ожидает, — например, вы поменяли порт Vite, не сказав серверу.

Запускайте обе части согласованно:

```bash
WEB_PORT=9000 pnpm dev
```

Ограничение намеренное: без него любой открытый в браузере сайт смог бы прочитать ваши токены через локальный API. Не расширяйте его до `origin: true`.

#### Интерфейс не реагирует на правки файлов извне

Живое обновление работает через слежение за файлами, и это настройка. Проверьте **Настройки → следить за файлами**. По умолчанию включено, но на сетевых файловых системах и в части контейнеров события файловой системы приходят ненадёжно — там лучше выключить и пользоваться кнопкой обновления.

### Не работает конкретный раздел

#### `claude` не найден / command not found

Всё, что работает через модель — чат, помощник форм, плагины, разговоры в песочнице, проверка MCP, — запускает `claude` CLI. Он должен быть в `PATH` того процесса, который запустил сервер.

```bash
claude --version
```

Если ваша оболочка его находит, а панель нет — значит сервер запущен из окружения, где его нет: терминал открыли до установки CLI или среда закэширована редактором. Закройте терминал, откройте новый и запустите `pnpm dev` заново.

<details>
<summary><b>Проверить, откуда он берётся</b></summary>

```powershell
(Get-Command claude).Source        # Windows
```

```bash
which claude                       # macOS / Linux
```

</details>

#### Чат отвечает «Not logged in»

CLI установлен, но не аутентифицирован. Запустите `claude` в терминале и войдите. Своего входа у панели намеренно нет — учётные данные остаются делом Claude Code.

По этой же причине чаще всего не работает песочница: она копирует `.credentials.json` из вашего настоящего каталога, и если файла ещё нет, копировать нечего.

#### Страница плагинов пуста или показывает ошибку CLI

Эта страница — тонкая обёртка над `claude plugin`. Проверьте команду напрямую:

```bash
claude plugin list --json
claude plugin list --available        # эта ходит в сеть
```

Получение каталога клонирует git-репозитории, поэтому нужны `git` и доступ в сеть, а в первый раз это может быть долго — панель ждёт три минуты. Всё, что печатает CLI, показывается вам без правок, и это осознанно.

#### MCP-сервер не подключается

Сначала проверьте команду руками — панель запускает ровно то, что записано у вас в конфигурации:

```bash
npx -y @modelcontextprotocol/server-filesystem ~/projects
```

Обычные причины:

- **Команды нет в `PATH`.** `npx`, `uvx` и `node` должны быть доступны процессу сервера.
- **Не хватает токена.** Серверам, которым нужны учётные данные, они берутся из `~/.claude/.mcp-secrets.env` — проверьте, что ключ есть и значение актуально. Истёкший токен обычно выглядит как рукопожатие, которое началось и оборвалось.
- **Долгий старт.** Запуску процесса даётся до 45 секунд — на первом запуске `npx` тянет пакет. Сетевым серверам отводится меньше: не ответивший за десяток секунд адрес не ответит и за минуту. Прогрейте кэш, запустив сервер один раз вручную.
- **Нужны заголовки.** Серверу со статическим токеном они задаются в форме сервера, поле «Заголовки запроса» (по строке на заголовок, `Имя=значение`). Без них проверка упрётся в 401.
- **Нужен интерактивный OAuth.** Сервер, который требует вход с редиректом, поддержан: у сетевых серверов есть кнопка «Авторизоваться». Она открывает окно входа; после авторизации токен сохраняется отдельным файлом (`claude-control/mcp-oauth.json`, права 600) и обновляется сам при истечении. Если окно не открылось — разрешите всплывающие окна для панели и нажмите ещё раз. Сбросить вход — кнопка «Выйти».

Рукопожатие по протоколу MCP делается для всех транспортов — stdio, HTTP и SSE, — и в ответе видно число инструментов. Встроенный пресет файловой системы подставляет ваш домашний каталог.

#### Аналитика пустая или с пробелами

Она читает `~/.claude/projects/*.jsonl`. Пусто — значит транскриптов нет: либо установка свежая, либо каталог конфигурации не тот.

Стоимость — оценка по прайсу Anthropic. На подписке за токены не списывают, поэтому число читается как объём, а не как деньги. Прайс подтягивается с сайта при открытии настроек (не чаще раза в сутки) и хранится в `claude-control/pricing-cache.json`; цена берётся по конкретной версии модели из транскрипта, а незнакомая модель считается по тарифу Sonnet. Нет сети — считаем по прошлому кэшу, а если его нет — по таблице, зашитой в панель; что именно в силе, видно в **Настройки → Тарифы для оценки стоимости** вместе с датой обновления и кнопкой «Обновить прайс». Там же можно задать свою цену — она перебивает прайс.

Раздел _«работающие агенты»_ опознаёт процессы по командной строке: установленный через npm CLI работает под именем `node`, поэтому по имени процесса он не находился. Если раздел пуст, а Claude Code запущен, — скорее всего система не даёт перечислять чужие процессы.

#### Песочница ведёт себя странно

Песочница — это намеренно почти пустой Claude Code: около 30 инструментов вместо 165, ни одного MCP-сервера, ни одного стороннего хука. Поведение, которое зависит от вашей обычной настройки, там не воспроизведётся — в этом и смысл.

Если модель говорит, что не может писать файлы, проверьте, что песочница вообще собралась: временный каталог каждый раз создаётся с нуля, и сбой на середине оставляет его неполным. Закройте песочницу и откройте заново.

#### Песочница отвечает «Not logged in»

Обычный чат при этом работает — значит дело не в аккаунте, а в том, что во временный каталог не попал токен. Начните с `pnpm doctor`: строка про учётные данные скажет, нашлись ли они и откуда.

На **macOS** это самая частая причина — токен лежит в связке ключей, а не файлом. Разбор и три способа починки: [Различия между системами → macOS](#macos-песочница-и-связка-ключей).

На **Windows и Linux** проверьте, что файл вообще есть:

```bash
ls -l ~/.claude/.credentials.json
```

Нет файла — войдите заново командой `claude` в терминале.

### Изменения не применяются

#### Claude Code игнорирует правку, сделанную в панели

**Почти наверняка нужен перезапуск.** Claude Code читает конфигурацию при старте. Панель такие изменения помечает, но плашку легко пропустить.

Закройте Claude Code полностью — все окна и все запущенные сессии — и запустите заново.

Если и после этого не применилось:

1. Проверьте, что сущность включена в панели.
2. Откройте файл и убедитесь, что правка действительно на диске (`~/.claude/CLAUDE.md`, `~/.claude/settings.json`).
3. Для хуков проверьте matcher: хук с не тем событием или шаблоном существует, но просто никогда не срабатывает. Прогон события в песочнице отвечает на это меньше чем за секунду и не тратит ни одного токена.
4. Для скиллов убедитесь, что папка лежит в `skills/`, а не в `skills-disabled/`, и что у `SKILL.md` корректный frontmatter — при битом YAML скилл не загружается, хотя выглядит на месте.

#### Файл выглядит неправильно после правки

Перед каждой записью делается резервная копия. Загляните в `~/.claude/claude-control/backups/` — там `<имя>.<метка-времени>.bak`; скопируйте нужную версию поверх оригинала. Хранятся последние десять копий каждого файла: иначе каталог рос бы без предела, а в нём лежат в том числе копии файла секретов.

Если копий нет, значит они отключены в **Настройках → делать резервную копию перед записью**. По умолчанию включено, и лучше не выключать.

### QA-скрипты

#### `Executable doesn't exist at .../chrome-...`

Не установлены браузеры Playwright:

```bash
pnpm qa:setup
```

На Linux это ещё и подтянет системные библиотеки, возможно, спросив `sudo`.

#### Скрипт не находит элемент

Скрипты работают по живому интерфейсу, поэтому ломаются при изменении вёрстки. Два из них к тому же рассчитаны на конфигурацию автора: `check-resources.mjs` ищет конкретное число файлов и конкретные имена скриптов и на любой другой машине упадёт по таймауту.

Перенаправить скрипт на другой адрес — переменной `APP_URL`:

```bash
APP_URL=http://127.0.0.1:9000 node tools/qa/screenshot.mjs light
```

Скриншоты складываются в `.qa-screenshots/`, эта папка в `.gitignore`. Запускать скрипты нужно из корня репозитория — пути к результатам считаются от рабочего каталога.

## Сбор диагностики

Начните с автоматической проверки — она покрывает почти всё, что спрашивают первым делом:

```bash
pnpm doctor
```

Если нужно описать проблему подробнее:

```bash
node --version
pnpm --version
claude --version
```

```bash
curl http://127.0.0.1:5178/api/location    # найденный каталог, валидность, чего не хватает
curl http://127.0.0.1:5178/api/system      # платформа, домашний каталог, Node, оболочка
curl http://127.0.0.1:5178/api/overview    # счётчики по разделам
```

Решающим обычно оказывается `/api/location`: он сообщает путь, по какому правилу он выбран, валиден ли и каких ожидаемых файлов не хватает.

Предупреждения и ошибки сервер пишет в терминал, где запущен. Проблемы фронтенда видны в консоли браузера (<kbd>F12</kbd>).

> Прежде чем делиться выводом, вычистите `/api/env`: он перечисляет имена переменных, и хотя значения секретов замаскированы, сами имена тоже бывают чувствительными.

## Как всё откатить

**Вернуть одну правку** — проще всего из панели: **Настройки → Резервные копии**, кнопка «Откатить» рядом с нужной копией. Файл заменяется целиком, а состояние до отката сохраняется новой копией — так что откатить можно и сам откат. Копии лежат в `~/.claude/claude-control/backups/` (последние десять на файл), и их по-прежнему можно скопировать руками.

**Сбросить саму панель** — удалите `~/.claude/claude-control/state.json`. Пропадут группы, сценарии и настройки панели; конфигурация Claude Code не пострадает.

**Удалить панель полностью:**

```bash
rm -rf ~/.claude-control          # рабочие папки чатов и песочницы
rm -rf ~/.claude/claude-control   # состояние панели и резервные копии
```

Дальше удалите репозиторий. Больше ничего не останется: ваши правила, скиллы, хуки и MCP-серверы — обычные файлы Claude Code, и они как лежали, так и лежат.

> [!TIP]
> Перед удалением загляните в `~/.claude-control/chats/` — там могли остаться нужные артефакты из разговоров, — и придержите `~/.claude/claude-control/backups/`, пока не убедитесь, что оттуда ничего не понадобится.
