## Открытый бэклог

### Проверка на живой машине

- **Прогон на macOS и Linux.** Код кроссплатформенный и покрыт тестами с подменой `process.platform`,
  но подмена — не запуск. Непроверенным остаётся: настоящий `which` и пути в `PATH`, права
  `0600`/`0700`, запуск CLI без обёртки `cmd.exe`, связка ключей macOS, чувствительность файловой
  системы к регистру. Два теста, которым нужен настоящий POSIX, честно помечены пропущенными.
- **Первая реальная запись у чужих CLI.** Aider, Cursor, OpenCode, Continue, Goose, Kimi Code и
  Qwen Code на машине разработки не установлены: их форматы собраны по документации и закрыты
  round-trip-тестами, но глазами первую запись никто не видел. Проверять по одному: поставить CLI,
  открыть раздел, записать, сверить файл вручную.
- **Автозапуск проекта через настоящий перезапуск панели.** Тумблер, память порта и подъём
  проектов при старте покрыты тестами; сценарий «выключил панель — включил — проект поднялся сам»
  вживую не проходили.
- **Запуск проекта на yarn и на не-Vite стеках.** Живьём проверены pnpm-монорепа (корень и пакеты),
  чтение порта из вывода Vite и сервер, слушающий только `::1`. Выбор yarn, а также Next, Angular и
  create-react-app закрыты тестами по их формату вывода, но настоящего проекта под рукой не было.

### Незакрытые разделы у чужих CLI

Границы и причины — в [LIMITATIONS-PROVIDERS.ru.md](docs/LIMITATIONS-PROVIDERS.ru.md); задачами из
них являются только пометки **задел**:

- **Continue:** отдельные файлы `~/.continue/mcpServers/*.yaml` (панель ведёт только блок
  `mcpServers` внутри `config.yaml`).
- **Goose:** `permission.yaml` — пофайловые разрешения инструментов (сейчас правится только режим
  `GOOSE_MODE`).
- **Богатый чат у чужих провайдеров:** у всех, кроме Claude и OpenCode, ассистент неинтерактивный —
  ответ приходит целиком, без стриминга и вложений.
