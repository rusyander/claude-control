# Engineering notes

- Prefer small functions with one job; name things after what they hold.
- Keep modules under four hundred lines; split by cohesion, not by size alone.
- Every bug fix carries a test that fails before the fix and passes after it.
- Use LF line endings; never commit generated files.
- Log the reason with every refusal; a silent skip is a defect.
- Read the code map before touching an unfamiliar module.
- Tests touch temp directories only, never the real home directory.
- Comments explain why, not what.
- Используй понятные имена и короткие функции.
- Keep error messages actionable: say what failed and what to do next.
