## Найдено аудитом (Фаза 4)

Жёсткий аудит пяти областей (чат, MCP+OAuth+песочница, редакторы конфига,
группы/настройки/бэкапы, аналитика) мультиагентом + написано ~157 тестов
(сервер 472→603, веб 172→198). Часть багов исправлена сразу и покрыта тестами;
остальные — те, что поначалу были отложены как `it.skip`/`it.todo`-тесты, —
**тоже исправлены на этой сессии**, а `skip` сняты (см. разделы ниже). Все баги
из этой фазы закрыты; открытых не осталось. Подробные репро — в
`.agent/tmp/audit-*.md`.

### Исправлено в ходе аудита (готово, покрыто тестами)

- **[HIGH]** `HookProbe.ts` — запись в `child.stdin` без обработчика `error`: хук,
  не читающий ввод и сразу выходящий, рвал канал → uncaught `EPIPE`/`EOF` →
  **падение всего процесса панели**. Добавлен `stdin.on('error')` + try/catch.
- **[MED]** `SandboxConfig.ts` — вырожденный id песочницы (`''`/`..`/`///`)
  схлопывался в пустоту → `rmSync(recursive)` в корне → **снос всех песочниц**
  (с копиями `.credentials.json`). Теперь throw на пустой id.
- **[MED]** `McpProbe.ts` — OAuth-токен не пробрасывался в стенд MCP песочницы
  (пробел #17): стенд всегда получал «требуется авторизация». Добавлен проброс.
- **[HIGH]** `analytics` — `/api/analytics?days=abc` → `new Date(NaN).toISOString()`
  ронял отчёт 500. Добавлена защита.
- **[MED]** выгрузка CSV не включала колонку `cacheCreation` (сумма не сходилась
  с `total`). Колонка добавлена; выгрузка вынесена в модуль `Analytics/model/report.ts`.
- **[LOW]** разбор прайса брал колонку `output` по первому совпадению вопреки
  своему комментарию; CSV без экранирования и защиты от инъекции формул
  (`=`,`+`,`-`,`@`) — добавлены RFC 4180 + гашение префикса.
- **[minor]** правка группы сбрасывала `order` в 0 (группа прыгала вверх) —
  `?? existing?.order ?? 0`, регресс-тест.

### Баги, исправленные ПОСЛЕ аудита (регресс-тесты, skip сняты)

Все перечисленные ниже открытые баги на этой же сессии **исправлены** тремя
фиксер-агентами, каждый закрыт регресс-тестом (ранее — `it.skip`/`it.todo`).
Гейт после фиксов зелёный: сервер 619 passed, веб 202 passed.

- **[MAJOR, ✅]** `entity-toggle.ts` — в `applyEntityState` не было ветки `permission`:
  переключение группы с участником-правом молча не пишется на диск (read-путь и
  conflict-UI фичу анонсируют). Достижимо через `importState`.
- **[MAJOR]** `group-routes.ts` (PUT) — не реконсилирует `disabledByGroup` при
  смене состава: убранный из выключенной группы участник заперт в disabled
  навсегда, без видимой причины.
- **[MED]** `rules.ts` — round-trip CLAUDE.md дописывает `ПРАВИЛО: ` к любому
  не-правило h2-заголовку (`## Обзор` → `## ПРАВИЛО: Обзор`); срабатывает даже
  при выключении одного правила — тихая мутация файла, который читает Claude.
- **[MED]** `hooks.ts moveHook` (код #9) — при перестановке ГЛОБАЛЬНОГО хука
  безусловно пишет в `settings.local.json`, создавая его пустым (`{"hooks":{}}`).
- **[MED]** `scripts.ts deleteScript` (код #3) — удаление скрипта БЕЗ резервной
  копии (необратимо), в отличие от `deleteSkill`; маршрут не возвращает `backupPath`.
- **[MED]** `analytics` — `byDay` режется по UTC-дате, `byHour` по локальному
  часу: одна запись попадает в «день» и «час» из разных суток.
- **[LOW-MED]** `rules.ts` — парсер рвётся о markdown-заголовки (`##`/`###`)
  внутри тела правила; в служебном разделе выключенное правило может частично
  «воскреснуть».
- **[LOW]** `scripts.ts` (код #3) — «используется» ложно срабатывает из-за
  `endsWith(rel)` без границы сегмента (`precheck.mjs` помечает `check.mjs`).
- **[LOW]** `safe-io`/`config-routes` — нет верхнего клампа глубины ротации на
  сервере: контракт задаёт max 100, а `setBackupKeep`/PATCH не валидируют.
- **[LOW]** `env` — `source='group'` при раскрытии секрета уходит в
  `.mcp-secrets.env`; удаление секрета оставляет осиротевший комментарий.
- **[LOW]** `mcp-oauth.ts` — гонка read-modify-write в `mcp-oauth.json`:
  параллельные писатели по одному `serverId` (вход + рефреш в health-check) могут
  затереть друг друга. Нужна сериализация записи по серверу.
- **[LOW]** прочее по чату: `translate` берёт только первый `tool_use` (при
  параллельных вызовах теряются остальные, вкл. `AskUserQuestion` → нет жёлтой
  точки); пер-чат оверрайд модели/effort и черновик теряются при превращении
  нового чата в реальный (ключ `home`→`chat:id`); `useChatStream` — мёртвый код.

### Функционал — доделано (корзины «желательно» и «косметика»)

Все доработки из аудита реализованы на этой сессии (каждая с тестом):

- расход при ретрае упавшего прогона не задваивается; `pumpStream` устойчив к битому SSE-фрейму;
  `active()` возвращает недавно завершённые успешные прогоны (лента догоняет хвост после F5);
- серверная валидация тел `PATCH /api/settings` и `POST /import` (zod на сервере, кривое → 400);
- выгрузка аналитики расширена: по моделям/проектам/сессиям + колонка стоимости; JSON без живых процессов;
- `PUT /api/claude-md` отклоняет не-строку (не затирает файл пустотой);
- дедуп транспорт-билдера, микро-перф (sort/env только при изменении), `looksLikePermission`
  согласован с сервером, `tryParse` устойчив к логам вокруг JSON, локализация `process.env`,
  уникальное имя tmp-файла, детерминизм дублей имён MCP; прайс-границы UTC — с обоснованием.

**Пойман и исправлен краш старта сервера:** серверная валидация ошибочно импортировала
zod-значения из `@claude-control/contracts` (барель не резолвится в рантайме Node) →
`ERR_MODULE_NOT_FOUND`. Схема перенесена в `apps/server/src/lib/settings-validation.ts`.

всех пакетах, тесты сервера и веба зелёные, линт без ошибок.

### Обязательное — панель обещала то, чего не делала

1. **Переменные группы не применялись.** Поле сохранялось и показывалось
   бейджем, но в `settings.json` не уходило. Теперь включение группы пишет её
   переменные, выключение снимает — с моделью отметок `envByGroup`, которая не
   трогает переменные, заданные вручную или другой группой.
2. **Скрипты `.ts` в песочнице не запускались** — команда собиралась как
   `bash script.ts`. Теперь `.ts/.mts/.cts` идут через
   `node --experimental-strip-types`.
3. **Вложенные папки в `hooks/` не показывались** — каталог читался плоско.
   Теперь обход рекурсивный, идентификатор скрипта — относительный путь; маршруты
   переведены на wildcard, чтобы `/` в id не ломал их.
4. **Счётчик расхода обнулялся при перезагрузке** — жил в памяти вкладки. Теперь
   накопление идёт на сервере вместе с реестром прогонов и переживает F5.

## Сюда не вошло

Не задачи. Оставлено в [LIMITATIONS.ru.md](LIMITATIONS.ru.md) как описание
границ продукта — там же сказано, почему каждое ограничение существует.

**Невозможно** (ограничение Claude Code, ОС или сети):

- остаток лимитов подписки — он на серверах Anthropic, локально его нет;
- время старта агентов на macOS и Linux — `ps` его не отдаёт;
- переименование скилла — имя папки и есть его идентификатор;
- гарантия исполнения правила — правило это инструкция, а не ограничение;
- приоритет между правилами — Claude читает файл целиком;
- объяснение, под какое правило попал запрос — панель пишет файлы, а не читает
  решения CLI;
- включение отдельных инструментов MCP-сервера — сервер подключается целиком;
- работа плагинов без сети и без `claude` в `PATH`;
- применение настроек без перезапуска Claude Code.

**Не нужно** (осознанные решения):

- своя база данных, история и синхронизация между машинами — источник правды
  это файлы, история версий это git;
- аутентификация в API — инструмент однопользовательский и слушает только
  `127.0.0.1`;
- проектные `.claude/settings.json` и `.mcp.json` — панель ведёт пользовательский
  уровень;
- шифрование секретов — ключ лежал бы рядом с шифром;
- удаление и переименование разговоров — транскрипты принадлежат Claude Code;
- полнотекстовый поиск по переписке — индекса нет, транскрипты слишком велики;
- выборочный откат одной настройки из копии — копия это снимок файла;
- восстановление в произвольный путь — имя копии приходит из запроса и не должно
  становиться путём записи;
- тумблер у локального хука — выключение означало бы удаление строки из личного
  файла;
- автоматическая проверка связи MCP при открытии страницы — поднять сервер стоит
  времени.
