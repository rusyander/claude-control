# Агент панели: управлять приложением словами

**Статус: код сделан 17.09.2026 (А0–А9).** Развилки §6 решены владельцем; позже он расширил объём: агент
умеет всё, что человек, во всех разделах, отвечает по справке и принимает голос (§6-5 отменён). Приёмка
на отдельном стенде с настоящим `claude` и заглушкой модели пройдена; вживую с настоящей моделью три
примера §1 не проверены.

## 1. Заказ

В самом приложении есть глобальный агент. Человек пишет ему обычным языком, и агент выполняет это в панели
теми же действиями, что человек сделал бы руками. Примеры владельца:

- «Перейди в чат и создай проект …»
- «Зайди в тестирование и напиши тест-кейсы для проекта …»
- «Зайди в контур и подключи новый контур, вот ссылка на dev-стенд (или прод) этого провайдера»

Агент доступен из любого раздела, видит, где человек сейчас находится, и после действия показывает
результат на экране, открывая нужную страницу.

## 2. Что есть сегодня

- **Помощник по заполнению форм** — `/api/assist` (`domains/assistant.ts`), окно
  `shared/ui/assistant-chat`. Возвращает текст для полей, ничего не делает сам.
- **Ассистент активного провайдера** — `/api/assistant/run` (`domains/assistant-runner/`): один
  разговор, CLI one-shot или прямой API, через контур — потребитель «Ассистент панели». Инструментов
  панели у него нет.
- **Переходники MCP панели** — `domains/panel-mcp.ts`: `tools/mcp/atlassian.mjs` и
  `tools/mcp/platform.mjs`. Принцип, который берём как есть: в окружение CLI уходит ТОЛЬКО адрес панели,
  переходник ходит в панель, наружу ходит уже она. Ключей и токенов процесс агента не видит. У
  переходника контура сейчас только чтение и вопросы: `contour_list`, `contour_ask_agent`,
  `contour_session`, `contour_reset_session`, `contour_ask_model`.
- **REST API панели** покрывает почти всё, что делает интерфейс: 60+ модулей в `apps/server/src/routes/`.
  Агент в чате уже может дёрнуть его через Bash, но это обход: ключ пришлось бы писать в чат, нет
  подтверждения и нет описания действий. Проверено 14.09: подключить контур без правки кода можно
  только так.

## 3. Эталонное решение (рекомендация)

1. **Реестр действий панели — одно место правды.** Каждое действие описано один раз: имя, схема
   входа (zod из `packages/contracts`), класс риска, какую страницу открыть после, какой маршрут API
   выполняет. Из реестра собираются инструменты MCP, подписи в карточке подтверждения и справка.
   Второго описания нет нигде, иначе разойдутся молча.
2. **Третий переходник `tools/mcp/panel.mjs`** по образцу двух существующих: только адрес панели,
   вызовы идут в маршрут `/api/agent/actions/:name`, который проверяет схему и класс риска. Агентом
   может быть любой CLI панели, в том числе идущий через контур.
3. **Классы риска.**
   - **Чтение** (списки, статусы, план запуска) — без вопросов.
   - **Изменение** (создать проект, записать кейсы, сохранить черновик контура) — карточка
     «что будет сделано» с диффом или предпросмотром и кнопкой «Выполнить».
   - **Опасное** (включить контур, применить к конфигам CLI, запустить агента, удалить) — то же
     подтверждение, отказ по умолчанию. Удаление и запись в `~/.claude` никогда не выполняются без
     клика.
4. **Секреты агент не видит никогда.** Действие, которому нужен ключ («подключи контур»), доходит до
   шага ключа и открывает в панели поле пароля. Человек вводит ключ туда, агенту возвращается только
   «ключ сохранён / отклонён». Ключ, вставленный в сообщение агенту, панель маскирует до отправки
   модели — фильтром данных, который уже есть.
5. **Навигация — тоже действие.** `open_page {route, focus}` — панель открывает страницу у человека
   через SSE `/api/events`; агент не кликает DOM. Сквозной путь через браузер остаётся для проверок.
6. **Одна точка входа в интерфейсе** — кнопка агента в шапке на всех страницах, плюс контекст
   «человек сейчас на странице X, выбран проект Y». Окно диалога — поверх страницы, история — в
   файлах панели, как у чата.
7. **След.** Каждое выполненное действие записывается в историю панели («Агент панели: подключён
   контур X, подтвердил человек»), чтобы действие агента не было неотличимо от действия человека.

## 4. Первый набор действий

| Раздел       | Чтение                                    | Изменение / опасное                                                                                                    |
| ------------ | ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Навигация    | где человек, список разделов              | `open_page`                                                                                                            |
| Проекты, чат | проекты, чаты, активные прогоны           | создать проект, новый чат с первым сообщением (опасное: запуск агента)                                                 |
| Тестирование | группы, кейсы, покрытие, последний прогон | черновик кейсов по описанию → предпросмотр → запись; запуск прогона (опасное)                                          |
| Контур       | контуры, статус, проба адреса             | мастер по ссылке: адрес → проба → поле ключа у человека → возможности → «Где работает» → сохранить; включить (опасное) |
| Конфигурация | правила, скиллы, хуки, MCP, права         | правка через те же маршруты, дифф в подтверждении                                                                      |

Конфигурацию берём последней: это файлы `~/.claude` владельца, там самая высокая цена ошибки.

## 5. Задачи (черновое дробление)

- **А0. Разведка и контракт.** Инвентарь маршрутов API против действий интерфейса: где действие есть
  только в клиенте. Схема реестра, классы риска, формат карточки подтверждения.
- **А1. Реестр и маршрут действий** на сервере: проверка схемы, класса риска, ожидающее подтверждение
  с таймаутом, запись в историю. Интеграционные тесты: отказ без подтверждения, повтор, чужой origin.
- **А2. Переходник `tools/mcp/panel.mjs`** и запись его в конфиг CLI через `panel-mcp.ts`.
  Проверка настоящим CLI: инструменты видны, вызов доходит, в окружении процесса нет секретов.
- **А3. Окно агента** в шапке, контекст страницы, карточка подтверждения, `open_page` через SSE.
  Доступность и клавиатура — в `panel-pages.mjs`.
- **А4. Действия «Навигация» + «Проекты, чат».**
- **А5. Действия «Тестирование»** (черновик кейсов с предпросмотром).
- **А6. Действия «Контур»**: мастер по ссылке, ключ только у человека.
- **А7. Действия «Конфигурация».**
- **А8. Телефон**: то же окно в `apps/mobile` поверх того же API.
- **А9. Справка** «Агент панели» с настоящими кадрами, сверка `sources.json`, враждебное ревью, полный
  гейт.

## 6. Развилки для владельца (решить до старта)

1. **Кто агент по умолчанию:** активный провайдер (рекомендация — тот же, что у чата, включая контур)
   или отдельно выбранная модель.
2. **Подтверждение изменений:** на каждое действие (рекомендация) или «доверять до конца разговора»
   для класса «Изменение».
3. **Живёт ли агент рядом с чатом** (тот же CLI-прогон с переходником) или как отдельное лёгкое окно
   без инструментов файловой системы. Рекомендация — отдельное окно: агенту панели не нужен доступ к
   файлам проектов, а меньше прав — меньше вреда.
4. **Телефон** — в первой партии или после.
5. **Голос** — не в объёме, пока не сказано иное.

## 7. Критерии приёмки партии

- Три примера из §1 выполняются вживую настоящим агентом, на экране владельца, с подтверждениями.
  Контур подключается к dev-стенду платформы компании по ссылке, ключ вводит человек.
- Доказательство — состояние панели после действия (файл, запись, карточка), а не текст ответа агента.
- В транскрипте агента, окружении его процесса и следе запросов нет ни одного ключа (проверка
  поиском, как в `check-chat-media`).
- Без подтверждения ни одно действие класса «Изменение» или «Опасное» не выполняется — сквозная
  проверка, где агента просят обойти карточку.
- Каждое действие реестра покрыто интеграционным тестом маршрута и описано в справке.
