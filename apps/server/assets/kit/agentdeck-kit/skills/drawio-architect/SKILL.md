# drawio-architect — the information-sheet standard

Deliverable: one uncompressed `.drawio` page an expert architect would sign off — an **information
sheet**: stage COLUMNS with coloured tab headers, dense text panes inside them, few short arrows, long
links on bus lanes above, and a bottom row of REFERENCE panels that are themselves mini-diagrams.
The reference sheet — this shape, not a variant of it. Anatomy:
[references/sheet-anatomy.md](references/sheet-anatomy.md).

The page is produced by a `generate.mjs` beside it, never by hand-written XML; it passes the mechanical
gate at `--strict`; it is read at 1:1 before it ships. Flow: _ground truth → interview → sheet plan →
generator → gate → eye → report_.

Size waiver: this skill deliberately exceeds default size budgets. Extend it and prune true
duplicates, but never shrink or summarize it to fit a budget.

**Edit mode** — the target `.drawio` already exists: read it whole first. Generated by a `generate.mjs`
→ edit the generator, regenerate, never patch the XML. Hand-made and following its own conventions →
those conventions are the design system for THAT file; house rules replace them only on the user's yes.
Untouched cells keep ids and coordinates; re-layout only the region the change lands in; new facts still
come from step 1. Bump version + date in the title block. `inventory.yaml` beside the file → refresh it
and report drift (drawn ≠ real). Gate runs on the whole file. Done when: the diff contains only what the
task required.

## 1. Ground truth

Inventory before drawing — the sheet states facts, never guesses.

- From code: entry points, deployable units (apps/services/workers/cron) with technology + version, data
  stores, queues/brokers, external SaaS/APIs, auth flows, infra manifests, configs with hosts/ports.
- From the spec: actors, features, integrations, constraints. Unknowns become an "Open questions" panel on
  the sheet and a line in the report — never an invented box.
- Facts that carry numbers (timeouts, limits, TTL, thresholds) are collected as they are found: they
  become the "Limits and ceilings" table.

Done when: `inventory.yaml` sits in the output folder — actors / systems / containers / stores /
externals / relations, every relation with direction + verb + technology, every row citing file or spec item.

## 2. Interview — in the user's language, the question tool

Only real forks; facts come from step 1, not from the user.

- Scope: "information sheet only" (recommended, default) / sheet + separate pages per layer —
  name which ones would join ([references/view-catalog.md](references/view-catalog.md)).
- Label language: the user's language (default) / English. Tech terms stay English either way.
- An existing `.drawio` in the repo → its conventions, or this skill's standard.

Skip every question the request already answers; "just do it" → all defaults, zero questions.

## 3. Sheet plan

Fill the fixed skeleton (sheet-anatomy §1) with this system's content:

1. **Columns** = stages of the request path, left → right, one per column: who → front → edge → runtime
   services → modules → data. A column that would hold one pane merges into its neighbour.
2. **Panes** per column: what the stage does, what it holds, its components, its stores, its notes.
   Every fact from the inventory lands in a pane or in a reference panel — nothing is dropped for
   layout's sake.
3. **Reference panels** = the questions the columns cannot answer in place: launch/entry forms, order of
   operations, state machines, status sets, failure paths, consequences of an action, code breaks, open
   questions, limits, where-to-look, glossary (catalogue: sheet-anatomy §4).
4. **Flows** = the coloured end-to-end paths (one colour per actor) that ride the bus lanes.

Announce it in Russian as a short list — columns, then reference panels — before writing the generator.

## 4. Generator

Write `<folder>/generate.mjs`; it is the source of truth, the `.drawio` is its output
(`node generate.mjs <ABSOLUTE out path>` — a relative path writes a stray copy under CWD). Helper
contract and proven code: [references/generator.md](references/generator.md). Visual language, the width
law, the alignment law, the readability law: [references/design-system.md](references/design-system.md).
Analyst marks the evidence supports: [references/analyst-annex.md](references/analyst-annex.md). XML
syntax under the helpers: [references/xml-format.md](references/xml-format.md).

Done when: the generator runs clean and every inventory row is on the page.

## 5. Gate

`node <kit>/skills/drawio-architect/scripts/validate.mjs --strict <file>` → `OK: N page(s)`.
Warnings are failures; fix the generator and rerun. A deviation that is genuinely deliberate (a foreign
file's conventions in edit mode) → rerun without `--strict` and name every surviving warning in the report.

## 6. Eye — the sheet is read before it ships

`node <kit>/skills/drawio-architect/scripts/shots.mjs <file> <folder>/shots` → PNG per page (+ PDF
when the draw.io CLI is installed; browser fallback needs network and produces no PDF — then report the
PDF as not produced). Read the full-page PNG, then re-render at device-scale 3 and crop regions with PIL
to read them 1:1. Hunt exactly these, they are what a reviewer catches:

- a box wider than its text, a table wider than its cells, a panel with an empty tail;
- cards of one row with different heights — their bottoms ragged, their arrow jogging;
- a legend whose swatches and captions sit on different lines, or whose rhythm is uneven;
- a label printing over a box or another label;
- an arrow crossing a card it has nothing to do with.
  Each one is fixed in the generator and the page is re-rendered. No renderer at all → say plainly:
  structure validated, not visually verified.

## 7. Report

Russian, short: folder path, what the sheet carries, open questions from step 1 (they are also ON the
sheet), drift found in edit mode, gate verdict, what was verified visually. Output goes where the user
said; unsaid → `<repo>/docs/architecture/<subject>/`: `architecture.drawio` · `generate.mjs` ·
`inventory.yaml` · `shots/page-1.png`.

## Red flags — self-check on the finished sheet

- A box, table or panel sized by its container instead of its text.
- A row of cards with ragged bottoms; a fan whose labels stack on one another.
- A relation missing, or drawn card→card where component→component was possible.
- A reference panel written as a bullet list where an arrow diagram was possible.
- A store drawn as a plain rectangle — stores are cylinders, externals clouds, services process boxes.
- A colour outside the design system; a legend missing a fill or an edge colour used on the page.
- An element the step-1 inventory cannot source, or an `inventory.yaml` disagreeing with the drawing.
