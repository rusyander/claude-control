## Требования

|                     | Минимум          | Проверить          | Примечание                                                                                       |
| ------------------- | ---------------- | ------------------ | ------------------------------------------------------------------------------------------------ |
| **Node.js**         | **22.6**         | `node --version`   | Ниже сервер не стартует вовсе — [почему](#сервер-падает-с-bad-option---experimental-strip-types) |
| **pnpm**            | 10               | `pnpm --version`   | `npm install -g pnpm`                                                                            |
| **Claude Code CLI** | любая актуальная | `claude --version` | Должен быть в `PATH` и залогинен                                                                 |
| **Git**             | любой            | `git --version`    | Нужен только для маркетплейсов плагинов                                                          |

В проекте лежит `.nvmrc`, поэтому `nvm use` подберёт версию Node сам.

**Windows, отдельной строкой — длинные пути.** Панель заводит параллельные рабочие копии
репозитория (`git worktree`) рядом с проектом, и путь внутри копии длиннее исходного. У глубокого
фронтенда он легко переваливает за 260 символов, а git без разрешения на длинные пути такие файлы
не видит вовсе — показывает их **удалёнными**, и `git add -A` внутри копии записал бы эти удаления
как настоящие. Один раз на машину:

```bash
git config --global core.longpaths true
```

Надёжнее включить длинные пути и в самой Windows (нужны права администратора): «Редактор локальной
групповой политики» → Конфигурация компьютера → Административные шаблоны → Система → Файловая
система → **«Включить длинные пути Win32»**, либо
`HKLM\SYSTEM\CurrentControlSet\Control\FileSystem\LongPathsEnabled = 1`. `pnpm doctor` проверяет оба
способа и молчит, если хотя бы один включён. Подробности и симптомы —
[Параллельные копии показывают удалённые файлы](#параллельные-копии-показывают-удалённые-файлы).

Claude Code должен быть именно **залогинен**: запустите `claude` один раз в терминале и пройдите
аутентификацию. Панель логинить не умеет — без этого чат, помощник, разговоры в песочнице и
плагины не работают.

## Установка

```bash
git clone <адрес-репозитория>
cd claude-control
pnpm install
pnpm qa:setup     # только если будете гонять браузерные QA-скрипты
```

## Где искать папку `.claude`

| Система     | Путь                    | Открыть командой                 |
| ----------- | ----------------------- | -------------------------------- |
| **Windows** | `C:\Users\<вы>\.claude` | `explorer %USERPROFILE%\.claude` |
| **macOS**   | `/Users/<вы>/.claude`   | `open ~/.claude`                 |
| **Linux**   | `/home/<вы>/.claude`    | `xdg-open ~/.claude`             |

Папка скрытая из-за точки: в проводнике включите **Вид → Скрытые элементы**, в Finder нажмите
<kbd>⌘</kbd><kbd>⇧</kbd><kbd>.</kbd>.

```
~/.claude/
├── CLAUDE.md              ваши правила
├── settings.json          хуки, права, переменные окружения
├── settings.local.json    личные хуки и права — в панели с пометкой «локальные»
├── skills/                по папке на скилл
├── hooks/                 скрипты хуков
├── projects/              транскрипты разговоров
├── .credentials.json      вход — руками не трогать (на macOS его нет, см. ниже)
├── .mcp-secrets.env       токены MCP (необязательный)
└── claude-control/        создаётся этой панелью
    ├── state.json         группы, сценарии, настройки панели
    └── backups/           копии перед записью (последние десять на файл)

~/.claude.json             MCP-серверы и аккаунт — ВНИМАНИЕ: рядом с .claude, не внутри
```

То, что `~/.claude.json` лежит рядом с папкой, а не внутри, — особенность самого Claude Code.

**Конфигурация в другом месте** (задан `CLAUDE_CONFIG_DIR` или другой диск) — панель найдёт её по
переменной, а иначе путь задаётся вручную в **Настройках → каталог конфигурации**; выбор
запоминается.

## Различия между системами

Панель ведёт себя одинаково везде, разбираться руками приходится с немногим. Проверить окружение
одной командой (ничего не меняет, объясняет каждую находку):

```bash
pnpm doctor
```

| Что              | Windows                     | macOS                               | Linux               |
| ---------------- | --------------------------- | ----------------------------------- | ------------------- |
| Запуск CLI       | `claude.cmd` через оболочку | `claude`                            | `claude`            |
| Учётные данные   | `.credentials.json`         | **связка ключей**, файла обычно нет | `.credentials.json` |
| Список процессов | PowerShell                  | `ps`                                | `ps`                |
| Сравнение путей  | без учёта регистра          | с учётом регистра                   | с учётом регистра   |

Всё это панель делает сама. Вмешательство нужно в одном случае — на macOS с песочницей.

### macOS: песочница и связка ключей

**Симптом.** Все разделы работают, обычный чат отвечает, а песочница говорит «Not logged in».

**Причина.** На Windows и Linux токен лежит файлом `~/.claude/.credentials.json`; на macOS — в
связке ключей, файла в каталоге нет. Песочница запускает Claude с подменённым
`CLAUDE_CONFIG_DIR`, и токен туда не попадает.

**Что делает панель.** Читает токен из связки сама (`security find-generic-password`). При первом
обращении система спросит разрешение — нажмите **Всегда разрешать**.

**Если не помогло** (например, запись в связке переименовали) — найдите имя и подставьте его:

```bash
security dump-keychain | grep -i -A1 claude
export CLAUDE_CONTROL_KEYCHAIN_SERVICE="Claude Code-credentials"
pnpm dev
```

**Способ, который работает всегда:** задать доступ вручную в панели — см.
[Доступ вручную](#доступ-вручную). Он перебивает автоматический источник.

**Если связка ключей недоступна** (корпоративная политика, запуск по SSH) — положить токен файлом:

```bash
security find-generic-password -s "Claude Code-credentials" -w > ~/.claude/.credentials.json
chmod 600 ~/.claude/.credentials.json
```

> [!WARNING]
> Это настоящий токен доступа к вашему аккаунту: права `600` обязательны, в репозиторий такой файл
> попадать не должен. Способ имеет смысл только там, где связка действительно недоступна: Claude
> Code обновит истёкший токен в связке, а файл останется старым и его придётся выгрузить заново.

### Доступ вручную

Запасной путь на любой системе, когда автоматический источник не находится или не подходит; он
**перебивает** автоматический. Нужен ровно одной вещи — **песочнице**: чат, помощник форм, плагины
и MCP запускают `claude` в вашем настоящем каталоге, где авторизацией занимается сам CLI.

1. **Настройки** → карточка **«Доступ Claude Code»**. Значок показывает текущий источник: _файл
   настроек_, _связка ключей macOS_, _задан вручную_, _ключ API_ или _не найден_.
2. **«Задать вручную»** → выберите образец и подставьте своё → **Сохранить**. Ввод проверяется
   сразу: неверный JSON или отсутствие нужного поля покажут ошибку в окне, а не потом отказом
   песочницы.
3. Кнопка **«Убрать ручной»** возвращает автоматический источник.

Три формы, любая на выбор — обязательно только одно поле из трёх:

```json
{
  "claudeAiOauth": {
    "accessToken": "sk-ant-oat01-…",
    "refreshToken": "sk-ant-ort01-…",
    "expiresAt": 1784000000000,
    "scopes": ["user:inference"]
  }
}
```

Токен подписки — то же, что в `.credentials.json`; минимум — непустой `accessToken`.

```json
{ "apiKey": "sk-ant-api03-…" }
```

Ключ Anthropic API — оплата пойдёт по тарифам API, а не по подписке.

```json
{ "readFrom": "/полный/путь/к/credentials.json" }
```

Токен лежит своим файлом в нестандартном месте.

Введённое сохраняется в `~/.claude-control/credentials.json` с правами `600` и в браузер не
отдаётся никогда — панель показывает только источник. Тот же файл можно создать руками.

**Порядок источников** (первый найденный побеждает): `~/.claude-control/credentials.json`
(вручную) → `<конфиг>/.credentials.json` (Windows, Linux) → связка ключей macOS →
`ANTHROPIC_API_KEY`.

### Linux и Windows

Особых шагов нет. На Linux файловая система различает регистр — путь к каталогу конфигурации
должен совпадать побуквенно (`~/.Claude` и `~/.claude` разные папки), а установка браузеров для QA
требует прав: `sudo pnpm qa:setup` (самой панели браузеры не нужны).

На Windows `claude.cmd` запускается через оболочку, аргументы с пробелами панель экранирует сама.
Конфигурация на другом диске:

```powershell
$env:CLAUDE_CONFIG_DIR = "D:\claude-config"
pnpm dev
```

## Первый запуск

```bash
pnpm dev
```

Поднимутся обе половины, браузер откроется сам.

|            | Адрес                 |                                         |
| ---------- | --------------------- | --------------------------------------- |
| **Панель** | http://localhost:8888 | то, чем пользуетесь                     |
| **API**    | http://127.0.0.1:5178 | только локально, наружу не выставляется |

По отдельности — когда отлаживаете что-то одно; свои порты — переменными:

```bash
cd apps/server && pnpm dev      # только API
cd apps/web && pnpm dev         # только фронтенд
PORT=5200 API_PORT=5200 pnpm dev
```

> [!WARNING]
> Меняете порт **фронтенда** — задайте серверу ещё и `WEB_PORT` (`WEB_PORT=9000 pnpm dev`): он
> принимает запросы только с origin своей панели, неожиданный origin получит 403.

При старте сервер печатает, где нашёл конфигурацию:

```
Claude Control API: http://127.0.0.1:5178
Каталог конфигурации: C:\Users\вы\.claude (источник: home)
```

`источник` — какое правило сработало: `manual` (задано в панели), `env` (`CLAUDE_CONFIG_DIR`),
`home` (по умолчанию) или `not-found`.

## Как убедиться, что всё работает

Сначала `pnpm doctor`, затем быстрый обход:

1. **Обзор** — ненулевые счётчики правил, скиллов и хуков. Нули везде — каталог не тот, смотрите
   строку `источник`.
2. **Правила** перечисляют разделы вашего `CLAUDE.md`.
3. **MCP** → _Проверить соединение_ возвращает список инструментов (проверка запуска процессов).
4. **Аналитика** показывает историю токенов (проверка чтения транскриптов).
5. **Чат** → отправьте «привет» — сквозная проверка `claude` CLI и лучший короткий тест.

Работают 1–2, но не 3–5 — панель в порядке, дело в CLI:
[`claude` не найден](#claude-не-найден--command-not-found).

## Починка

### Ничего не запускается

#### Сервер падает с `bad option: --experimental-strip-types`

Слишком старый Node: сервер исполняет TypeScript напрямую, нужен **22.6+**.

```bash
node --version        # v20.x или v22.5 и ниже — причина в этом
nvm install 22 && nvm use 22
```

Без `nvm` поставьте Node с [nodejs.org](https://nodejs.org) и перезапустите терминал — в открытом
остаётся старый `PATH`.

#### `EADDRINUSE: address already in use 127.0.0.1:5178`

Порт занят, почти всегда сервером из прошлого сеанса.

```powershell
# Windows
Get-NetTCPConnection -LocalPort 5178 -State Listen |
  Select-Object -ExpandProperty OwningProcess | ForEach-Object { Get-Process -Id $_ }
Stop-Process -Id <pid> -Force
```

```bash
# macOS / Linux
lsof -i :5178
kill -9 <pid>
```

Либо переехать: `PORT=5200 API_PORT=5200 pnpm dev`. С портом фронтенда строже — включён
`strictPort`, Vite молча на 8889 не уползёт, освобождайте 8888 тем же способом.

> `node --watch` следит за дочерним процессом: убили именно дочерний — родитель остаётся в
> неопределённом состоянии. Остановите сервер полностью и запустите заново.

#### `pnpm: command not found`

```bash
npm install -g pnpm
```

Заменять на `npm install` нельзя: это pnpm-workspace, npm неправильно свяжет `packages/contracts`.

#### Установка падает из-за несоответствия lock-файла

```bash
rm -rf node_modules apps/*/node_modules packages/*/node_modules
pnpm install
```

Не помогло — `pnpm install --no-frozen-lockfile` подберёт версии заново, ценой расхождения с lock.

---

### Панель работала и выключилась сама

Через несколько часов простоя стенд может исчезнуть целиком или наполовину: API отвечает, а фронтенд нет — или наоборот. Панель при этом не падала. Её убирает системный уборщик процессов: `pnpm dev` растёт из давно закрытой оболочки, поэтому всё дерево выглядит осиротевшим, а пощажены обычно только процессы, держащие сокет, — верхние `pnpm`, `cmd` и `node --watch` умирают, и одна половина стенда остаётся жить одна.

Лечится сторожем из самого репозитория:

```bash
pnpm keepalive:install   # поставить в автозапуск пользователя
pnpm keepalive:status    # что происходит сейчас
pnpm keepalive:off       # снять
```

Сторож раз в 20 секунд стучится в оба порта обычным TCP-подключением — не HTTP, потому что при включённом токене удалённого доступа живая панель отвечает 401, — и после двух молчаний подряд поднимает именно ту половину, которая замолчала. Уже работающий стенд он подхватывает, а не отбирает у него порт. Журнал: `%LOCALAPPDATA%\claude-control\keepalive.log`.

### Панель открылась, но пустая или сломана

#### Во всех разделах нули

Панель читает не тот каталог.

1. Посмотрите строку запуска сервера или **Настройки** — там путь и его источник.
2. Убедитесь, что по пути лежат `CLAUDE.md` и `settings.json`
   ([что должно быть внутри](#где-искать-папку-claude)).
3. Неверный путь задайте в **Настройках → каталог конфигурации**: некорректный не применяется,
   «увести» панель в никуда не получится.

Частая причина — забытая переменная после экспериментов:

```bash
echo $CLAUDE_CONFIG_DIR          # macOS / Linux
echo $env:CLAUDE_CONFIG_DIR      # Windows PowerShell
```

#### `127.0.0.1:8888` не отвечает, а `localhost:8888` открывается

Там, где `localhost` резолвится в `::1`, привязанный к нему dev-сервер поднимается только на IPv6.
В `apps/web/vite.config.ts` поэтому явно прописан `host: '127.0.0.1'` — если убрали, верните.

#### Запросы возвращают 403

API принимает как origin только собственную панель: поменяли порт Vite, не сказав серверу —
запускайте согласованно, `WEB_PORT=9000 pnpm dev`. Ограничение намеренное: без него любой открытый
сайт прочитал бы ваши токены через локальный API. Не расширяйте до `origin: true`.

#### Интерфейс не реагирует на правки файлов извне

Живое обновление — это слежение за файлами, **Настройки → следить за файлами**. По умолчанию
включено, но на сетевых ФС и в части контейнеров события приходят ненадёжно: там лучше выключить и
пользоваться кнопкой обновления.

### Не работает конкретный раздел

#### `claude` не найден / command not found

Всё, что работает через модель, запускает `claude` CLI, и он должен быть в `PATH` того процесса,
который запустил сервер.

```bash
claude --version
(Get-Command claude).Source        # Windows: откуда он берётся
which claude                       # macOS / Linux
```

Оболочка находит, а панель нет — сервер запущен из окружения, где его нет (терминал открыли до
установки CLI или среду закэшировал редактор). Откройте новый терминал и запустите `pnpm dev`.

#### Чат отвечает «Not logged in»

CLI установлен, но не аутентифицирован: запустите `claude` в терминале и войдите. Своего входа у
панели намеренно нет. По этой же причине чаще всего не работает песочница — она копирует
`.credentials.json`, а копировать нечего.

#### Страница плагинов пуста или показывает ошибку CLI

Страница — тонкая обёртка над `claude plugin`, проверьте команду напрямую:

```bash
claude plugin list --json
claude plugin list --available        # эта ходит в сеть
```

Получение каталога клонирует git-репозитории, поэтому нужны `git` и сеть; в первый раз это долго —
панель ждёт три минуты. Вывод CLI показывается вам без правок, и это осознанно.

#### MCP-сервер не подключается

Сначала проверьте команду руками — панель запускает ровно то, что записано в конфигурации:

```bash
npx -y @modelcontextprotocol/server-filesystem ~/projects
```

- **Команды нет в `PATH`.** `npx`, `uvx` и `node` должны быть доступны процессу сервера.
- **Не хватает токена.** Учётные данные берутся из `~/.claude/.mcp-secrets.env`; истёкший токен
  выглядит как рукопожатие, которое началось и оборвалось.
- **Долгий старт.** Запуску процесса даётся 45 секунд (на первом запуске `npx` тянет пакет),
  сетевым серверам — меньше. Прогрейте кэш, запустив сервер вручную.
- **Нужны заголовки.** Задаются в форме сервера, поле «Заголовки запроса» (`Имя=значение`, по
  строке на заголовок). Без них проверка упрётся в 401.
- **Нужен интерактивный OAuth.** У сетевых серверов есть кнопка «Авторизоваться»: токен
  сохраняется в `claude-control/mcp-oauth.json` (права 600) и обновляется сам. Окно не открылось —
  разрешите всплывающие окна. Сбросить вход — «Выйти».

Рукопожатие делается для всех транспортов (stdio, HTTP, SSE), в ответе видно число инструментов.

#### Аналитика пустая или с пробелами

Читает `~/.claude/projects/*.jsonl`. Пусто — транскриптов нет: свежая установка либо не тот
каталог.

Стоимость — оценка по прайсу Anthropic. Прайс подтягивается с сайта при открытии настроек (не чаще
раза в сутки) в `claude-control/pricing-cache.json`; цена берётся по конкретной версии модели из
транскрипта, незнакомая модель считается по тарифу Sonnet. Нет сети — прошлый кэш, а без него
зашитая таблица; что в силе, видно в **Настройки → Тарифы для оценки стоимости** вместе с датой и
кнопкой «Обновить прайс». Там же задаётся своя цена — она перебивает прайс.

Раздел _«работающие агенты»_ опознаёт процессы по командной строке (npm-установка работает под
именем `node`). Пусто при запущенном Claude Code — скорее всего система не даёт перечислять чужие
процессы.

#### Песочница ведёт себя странно

Песочница — намеренно почти пустой Claude Code: ~30 инструментов вместо 165, ни одного MCP-сервера
и стороннего хука. Поведение, зависящее от вашей обычной настройки, там не воспроизведётся — в
этом и смысл. Если модель говорит, что не может писать файлы, — вероятно, временный каталог
собрался не до конца: закройте песочницу и откройте заново.

#### Параллельные копии показывают удалённые файлы

**Симптом.** Вкладки задач разом краснеют; агент внутри параллельной копии сообщает, что дерево
грязное, и предлагает «починить longpaths и восстановить». В выводе git при этом видно

```
warning: could not open directory 'путь/подлиннее/…': Filename too long
 D путь/подлиннее/…/Component.tsx
```

**Причина.** Windows считает 260 символов на весь путь. Копия лежит по адресу
`<родитель>/<репозиторий>-worktrees/<ветка>/…`, то есть длиннее исходного репозитория, и у глубокого
фронтенда запас кончается. Файлы на диске есть, но git их не открывает и честно считает удалёнными.
Опасно это не красным цветом: `git add -A` в такой копии записал бы удаление настоящих файлов.

**Что делает панель.** Заводя копию, она включает `core.longpaths` в конфиге самого репозитория —
конфиг общий у всех копий, поэтому одной записи хватает и на основную, и на все параллельные.
Своим вызовам git панель разрешает длинные пути всегда, но агент внутри копии — чужой процесс со
своим конфигом, и его это не касалось бы.

**Что сделать самому.** Разрешить длинные пути один раз на машину — тогда защищены все репозитории,
включая те, где копий ещё не заводили:

```bash
git config --global core.longpaths true
git worktree prune          # в репозитории, где копии уже ломались
```

Общесистемная настройка Windows (пункт групповой политики «Включить длинные пути Win32» или
`LongPathsEnabled = 1` в реестре) снимает ограничение шире — не только для git. `pnpm doctor`
показывает, включено ли хоть что-то из двух.

#### Песочница отвечает «Not logged in»

Обычный чат при этом работает — значит дело не в аккаунте, а в том, что во временный каталог не
попал токен. Начните с `pnpm doctor`: строка про учётные данные скажет, нашлись ли они и откуда.

На **macOS** это самая частая причина, разбор и три способа починки —
[Различия между системами → macOS](#macos-песочница-и-связка-ключей). На **Windows и Linux**
проверьте, что файл есть (`ls -l ~/.claude/.credentials.json`); нет — войдите заново командой
`claude`.

### Изменения не применяются

#### Claude Code игнорирует правку, сделанную в панели

**Почти наверняка нужен перезапуск** — конфигурация читается при старте, панель такие изменения
помечает, но плашку легко пропустить. Закройте Claude Code полностью, со всеми сессиями.

Если и после этого не применилось:

1. Проверьте, что сущность включена в панели.
2. Откройте файл и убедитесь, что правка действительно на диске.
3. Для хуков проверьте matcher: хук с не тем событием существует, но никогда не срабатывает.
   Прогон события в песочнице отвечает на это за секунду и не тратит ни одного токена.
4. Для скиллов — папка в `skills/`, а не в `skills-disabled/`, и у `SKILL.md` корректный
   frontmatter: при битом YAML скилл не загружается, хотя выглядит на месте.

#### Файл выглядит неправильно после правки

Перед каждой записью делается резервная копия: `~/.claude/claude-control/backups/`,
`<имя>.<метка-времени>.bak` — скопируйте нужную версию поверх оригинала. Хранятся последние десять
на файл. Копий нет — они отключены в **Настройках → делать резервную копию перед записью**
(по умолчанию включено, лучше не выключать).

### QA-скрипты

`Executable doesn't exist at .../chrome-...` — не установлены браузеры Playwright: `pnpm qa:setup`
(на Linux подтянет и системные библиотеки, возможно, спросив `sudo`).

Скрипты работают по живому интерфейсу и ломаются при изменении вёрстки. Два рассчитаны на
конфигурацию автора: `check-resources.mjs` ищет конкретное число файлов и имена скриптов и на
другой машине упадёт по таймауту. Адрес переопределяется переменной:

```bash
APP_URL=http://127.0.0.1:9000 node tools/qa/screenshot.mjs light
```

Скриншоты складываются в `.qa-screenshots/` (в `.gitignore`); запускать из корня репозитория —
пути к результатам считаются от рабочего каталога.

## Доступ с телефона

Приложение `apps/mobile` разговаривает с той же панелью по тому же API. Ничего в интернет не
публикуется: сервер как слушал `127.0.0.1`, так и слушает, а туннель обрывается на этой же машине и
ходит на loopback.

Порядок — четыре шага, и первый из них выключен по умолчанию:

1. **Настройки → Удалённый доступ → включить.** Панель выдаст токен и покажет его QR-кодом. Токен
   виден ровно один раз: API его больше не возвращает, а «Обновить токен» отзывает старый вместе со
   всеми спаренными устройствами.
2. **`pnpm remote`** — поднимает Tailscale Serve перед API и печатает адрес вида
   `https://<машина>.<хвост>.ts.net`. Обратно — `pnpm remote:off`.
3. **Спарить телефон**: в приложении «Настройки → Спарить» навести камеру на QR. Вручную — тот же
   адрес и тот же токен двумя полями.
4. **`pnpm mobile`** — собрать и поставить приложение на подключённый телефон или эмулятор
   (нужны Android Studio SDK либо Xcode). Готовый файл для установки руками — `pnpm mobile:apk`:
   кладёт `claude-control.apk` в корень репозитория, заменяя прежний. Нужен Android 12 и новее.

Требования, которые панель за вас не выполнит:

- **Tailscale установлен и вошёл в ваш аккаунт**, в тайлнете включены HTTPS-сертификаты. Нет
  Tailscale — панель честно скажет, что адреса нет, и не станет его выдумывать. Телефон должен быть
  в том же тайлнете.
- **Push-уведомления требуют `eas init` под вашим аккаунтом Expo и проекта Firebase (FCM).** Пока их
  нет, приложение говорит об этом прямо на экране; о конце работы агента оно всё равно сообщит
  локальным уведомлением, пока живо в фоне.

Проверка без телефона:

```bash
curl -H "Authorization: Bearer <токен>" http://127.0.0.1:5178/api/system   # 200
curl http://127.0.0.1:5178/api/system                                      # 401 при включённом доступе
```

Первый ответ 401 с правильным токеном — почти всегда пробел или перенос строки, приехавший вместе с
токеном при копировании.

Адрес в тайлнете **закреплён за машиной**: перезагрузка, выключение и включение клиента, переход с
Wi-Fi на мобильный интернет его не меняют — перепаривать телефон не нужно. Меняется он, только если
машину удалить из тайнета или переименовать.

**Сборка занимает место — и убирает за собой.** Gradle кладёт объектные файлы каждой нативной
библиотеки внутрь неё самой, в `node_modules/<пакет>/android/build` и `.cxx`: одна релизная сборка —
около 10 ГБ, и в APK из этого не попадает ничего. Поэтому `pnpm mobile:apk` стирает их сразу после
того, как APK лёг в корень репозитория; собираете несколько раз подряд — `pnpm mobile:apk
--keep-build`, тогда пересборка быстрее. Осталось от прерванной сборки — `pnpm mobile:clean`
(`--dry` покажет объём, не удаляя), и `pnpm doctor` сам предупредит, если накопилось больше 2 ГБ.

## Сбор диагностики

```bash
pnpm doctor                                # покрывает почти всё, что спрашивают первым делом
node --version && pnpm --version && claude --version

curl http://127.0.0.1:5178/api/location    # найденный каталог, валидность, чего не хватает
curl http://127.0.0.1:5178/api/system      # платформа, домашний каталог, Node, оболочка
curl http://127.0.0.1:5178/api/overview    # счётчики по разделам
```

Решающим обычно оказывается `/api/location`: путь, по какому правилу он выбран, валиден ли и каких
файлов не хватает. Предупреждения сервер пишет в терминал, где запущен; проблемы фронтенда — в
консоли браузера (<kbd>F12</kbd>).

> Прежде чем делиться выводом, вычистите `/api/env`: значения секретов замаскированы, но сами имена
> переменных тоже бывают чувствительными.

## Как всё откатить

**Вернуть одну правку** — **Настройки → Резервные копии**, кнопка «Откатить». Файл заменяется
целиком, состояние до отката сохраняется новой копией, так что откатить можно и сам откат. Копии
лежат в `~/.claude/claude-control/backups/` (последние десять на файл) и копируются руками.

**Сбросить саму панель** — удалите `~/.claude/claude-control/state.json`: пропадут группы,
сценарии и настройки панели, конфигурация Claude Code не пострадает.

**Удалить панель полностью:**

```bash
rm -rf ~/.claude-control          # рабочие папки чатов и песочницы
rm -rf ~/.claude/claude-control   # состояние панели и резервные копии
```

Дальше удалите репозиторий — больше ничего не останется: ваши правила, скиллы, хуки и MCP-серверы
это обычные файлы Claude Code.

> [!TIP]
> Перед удалением загляните в `~/.claude-control/chats/` — там могли остаться нужные артефакты из
> разговоров, — и придержите `backups/`, пока не убедитесь, что оттуда ничего не понадобится.
