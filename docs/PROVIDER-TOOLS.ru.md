# Провайдеры: инструменты панели

Продолжение [Провайдеры: детали форматов](PROVIDERS.ru.md). Там — что панель правит в файлах
каждого CLI; здесь — инструменты, которые работают ПОВЕРХ провайдеров: перенос окружения, каталог
моделей, проверка на вашей машине, предпросмотр записи, сравнение конфигураций, сверка форматов
со схемами и свой эндпоинт вместо облака вендора.

## 1. Перенос окружения между машинами

Кнопки «Экспорт» и «Импорт» есть у каждого провайдера в разделе «Настройки»; каждая работает
только со своим. Экспорт собирает zip-архив: `MANIFEST.json`, `README.md` и файлы окружения —
инструкции, MCP-серверы, права, хуки, скиллы, агенты, команды, плагины, правила. Перед сборкой
показывается предпросмотр (сколько файлов, из каких каталогов), после — путь к готовому архиву.

Пути в манифесте не абсолютные: хранятся места конфигурации провайдера и относительные имена
внутри них, поэтому архив с Windows разворачивается на macOS и Linux по их собственным путям.

Секретов в архиве нет намеренно. Файлы доступа и токенов (`.credentials.json`,
`.mcp-secrets.env`, `provider-keys.enc`, `*.pem`, `*.key` и подобные) не попадают целиком; значения
с ключевыми именами (`api_key`, `token`, `secret`, `password`…) заменяются на `__REDACTED__` в
JSON, YAML, TOML и ini. Взамен манифест несёт чек-лист: что именно нужно ввести руками на новой
машине.

Импорт разбирает архив и по каждому файлу говорит: `new` (появится впервые), `same` (уже лежит
такой же), `differs` (перезапишет ваш) или `unresolved` (место не определилось). По умолчанию
отмечено только новое. Перед записью делается резервная копия, запись атомарная. Единственное
исключение из режима «файлом» — `~/.claude.json`: оттуда переносится только ключ `mcpServers`,
слиянием, чтобы не затереть остальную часть файла.

Из архива исключены тяжёлые и бессмысленные для переноса каталоги: `projects/`, `todos/`,
`history/`, `sessions/`, `logs/`, `plugins/marketplaces/`, кэши, `node_modules`, виртуальные
окружения Python (по `pyvenv.cfg`), сборочные папки. Ограничения: 5 МБ на файл, 64 МБ на архив;
файлы берутся по приоритету (`skills`, `hooks`, `agents`, `commands`, `rules`, `memory` и прочее
важное — первыми), а всё, что не поместилось, перечислено в манифесте.

## 2. Каталог моделей

Панель узнаёт список моделей провайдера сама: раздел «Настройки» → карточка «Модели провайдера».
Источник — открытый каталог [models.dev](https://models.dev/api.json), тот же, которым живёт
OpenCode: своего публичного списка моделей без ключа нет ни у Anthropic, ни у OpenAI, ни у Google.
Запрос уходит не чаще раза в сутки, ответ кэшируется в `claude-control/models-cache.json`; нет
сети — показывается прошлый список с отметкой давности, а не пустота.

Вендор объявлен в `providers/catalog.ts` полем `modelVendors`: claude → `anthropic`, codex →
`openai`, gemini → `google`, qwen → `alibaba`, kimi → `moonshotai`, opencode → его собственный шлюз
`opencode`. У Continue, Goose, Aider и Cursor вендора нет намеренно: это оболочки поверх любых
моделей, и панель не решает за пользователя, чей список ему показать (fail-closed).

Модель по умолчанию панель переставляет сама, когда включён тумблер «обновлять список моделей
самой» (по умолчанию включён). Границы узкие: только внутри одного семейства
(`claude-opus` → `claude-opus`), только вперёд по дате выхода и только если в настройках стоит
КОНКРЕТНАЯ модель из каталога. Алиас (`opus`), пустое значение и незнакомая строка не трогаются:
алиас CLI и так разворачивает в последнюю модель. О состоявшейся замене панель говорит сообщением.

Встроенный ассистент панели (тот, что заполняет формы по API-ключу) поднимает свою зашитую модель
до актуального поколения того же семейства — семейство здесь и есть страховка по деньгам:
`gpt-mini` остаётся `gpt-mini` и не превращается во флагман.

Что панель из каталога НЕ читает: ключ `experimental` там описывает экспериментальные режимы
модели (например, ускоренный со своей ценой), а не «превью-модель», поэтому в интерфейс он не
выносится вовсе.

## 3. Проверка провайдера

Бейдж «экспериментально» говорит о том, что формат собран по документации и прогнан тестами, но на
вашей машине панель его ни разу не исполняла. Кнопка «Проверить» в настройках меняет это обещание
на факт: она прогоняет короткий чек-лист здесь и сейчас.

Что проверяется:

| Шаг                    | Что доказывает                                                      |
| ---------------------- | ------------------------------------------------------------------- |
| CLI в PATH             | панель сможет запустить инструмент                                  |
| Файлы конфигурации     | каталог/файл провайдера на месте                                    |
| Круг записи по разделу | адаптер разобрал ВАШ файл, пересобрал его и получил ту же семантику |
| Запуск ассистента      | канал до модели живой: один короткий ответ пришёл                   |

**Ваши файлы проверка не меняет.** Круг «прочитали → записали → прочитали» идёт по временной копии
конфигурации, копия удаляется сразу после. Для MCP и переменных окружения в копию добавляется
пробная запись и тут же удаляется — так проверяется и добавление, и удаление; для прав и инструкций
записывается ровно то, что прочитано.

Итог: **проверен здесь** — прошли все шаги, включая ответ модели; **проверен частично** — отказов
нет, но что-то пропущено (нет CLI, запуск ассистента был выключен); **проверка не пройдена** — есть
отказавший шаг, и его причина написана строкой. Пропущенный шаг не считается ни успехом, ни
провалом: у Claude, например, MCP и права живут на собственных маршрутах панели, и универсальный
круг записи к ним не применяется.

Итог виден в карточке выбора провайдера и полосой над каждым разделом — настройки чужого CLI
правятся не на странице выбора. Проверка на вашей машине всегда важнее объявленного статуса, в обе
стороны: провалившаяся проверка перебивает даже «проверено» у Claude.

## 4. Предпросмотр записи

Конфигурацию чужого CLI человек ведёт руками. Панель приходит туда гостем, а кнопка «Сохранить» до
сих пор ничего не показывала до того, как станет поздно. Теперь между кнопкой и файлом стоит дифф.

Появляется на записи в любой раздел чужого провайдера: MCP-серверы, права, переменные окружения,
инструкции. У Claude предпросмотра нет — это дефолт панели, его форматы проверены, и лишний вопрос
на каждое сохранение был бы шумом. Выключается тумблером «показывать дифф перед записью» в карточке
безопасности настроек; резервная копия перед записью делается независимо, это отдельная настройка.

Дифф — не предсказание. Панель копирует ваш файл во временный каталог, выполняет по копии
**настоящую** запись тем же кодом адаптера, читает результат, копию удаляет. Показано ровно то, что
окажется в файле. Черновик отвергается теми же проверками, что и запись: если он негоден,
предпросмотр говорит об этом и кнопки «всё равно записать» не предлагает — иначе он был бы добрее
самой записи.

Дифф бывает шире правки: TOML и JSON панель пересобирает целым разделом, поэтому соседняя запись
может вернуться в другом написании при том же смысле (`args = ["x"]` → `args = [ "x" ]`). Это не
ошибка — но увидеть это лучше до записи, а не после.

| Ответ сервера         | Что значит                                        |
| --------------------- | ------------------------------------------------- |
| `section_unsupported` | у активного провайдера такого раздела нет         |
| `invalid_draft`       | черновик не прошёл валидацию — запись тоже упадёт |
| `format_unrecognized` | файл не разобрался; править его панель не станет  |

## 5. Сравнение конфигураций и перенос между CLI

Раздел «Сравнение» — про двух провайдеров сразу, поэтому от активного не зависит. Слева по
умолчанию активный CLI, справа любой другой; панель читает файлы обеих сторон и показывает разницу
по разделам: MCP-серверы, переменные окружения, права, глобальные инструкции.

Сравнение идёт **по смыслу, а не по тексту**: один и тот же сервер в TOML и в JSON записан
по-разному, и построчный дифф объявил бы разным всё подряд. Значения разбираются адаптерами и
сравниваются нормализованными.

Что видно в строке: `одинаково` (запись есть с обеих сторон и значения совпадают), `отличается`
(имя одно, параметры разные), `только слева` / `только справа`. Секреты — переменные, чьё имя
похоже на ключ или токен, — показаны маской и сверяются **только по наличию**: значение секрета
панель не показывает и не сравнивает.

Права помечены «модели разные»: у восьми CLI разные модели согласований, и совпадение имён ключей не
означает совпадения смысла. Они показаны рядом как справка.

### Что переносится

| Раздел                | Перенос | Почему                                                               |
| --------------------- | ------- | -------------------------------------------------------------------- |
| MCP-серверы           | да      | есть межвендорная модель и настоящие адаптеры записи с обеих сторон  |
| Глобальные инструкции | да      | это обычный файл: текст источника заменяет текст приёмника           |
| Переменные окружения  | нет     | в них хранятся ключи, а секреты панель в чужие конфигурации не пишет |
| Права                 | нет     | перевод одного режима согласований в другой был бы догадкой          |

Не переносятся также выключенные серверы и транспорт `sse` — у других CLI его нет. Причина написана
под строкой, а галочка недоступна: молча пропустить панель ничего не может.

Перенос всегда в два шага: отметить записи → кнопка направления → **дифф целевого файла**, снятый на
временной копии, → «Записать». Отмена не пишет ничего; при подтверждении делается резервная копия
(если она включена в настройках). Перенос инструкций — копия, а не слияние.

## 6. Сверка форматов со схемами

Панель пишет чужие конфигурации по документации, а документация уезжает вместе с релизами CLI.
Сегодня всё сходится, через два релиза ключ переехал — и узнаёт об этом пользователь, у которого
CLI перестал стартовать. Карточка «Сверка форматов со схемами» в настройках задаёт тот же вопрос
заранее: ключи, которые панель РЕАЛЬНО правит, всё ещё есть в официально опубликованной схеме?

Сравниваются **наши ключи со схемой**, а не ваш файл с чем-либо: конфигурацию сверка не читает и
не трогает вовсе. Расхождение ничего не блокирует и ничего не чинит — это повод заглянуть в
документацию CLI перед следующей записью в этот раздел.

| Состояние      | Что значит                                                              |
| -------------- | ----------------------------------------------------------------------- |
| `сходится`     | все ведомые ключи нашлись в схеме                                       |
| `расхождение`  | какого-то ключа в схеме нет — документация и схема разошлись            |
| `схемы нет`    | официальной схемы у этого CLI не публикуется, сверять не с чем          |
| `не проверено` | схема есть, но её не удалось скачать или разобрать (сеть, 404, не JSON) |

Проверяется сейчас **только OpenCode**: его схема опубликована по задокументированному адресу
`https://opencode.ai/config.json` и стоит в `$schema` его же примеров конфигурации. Ведомые ключи —
`mcp`, `permission` и `plugin`: сверяется ровно то, что панель пишет.

**Зачем это нужно, видно на первом же прогоне.** В списке был четвёртый ключ — `experimental.hook`,
на нём держались хуки OpenCode. Сверка показала, что в опубликованной схеме его больше нет:
у `experimental` перечислены другие ключи, а `additionalProperties` закрыт, то есть схема такой
ключ отвергает; справочник конфигурации это подтвердил. Раздел хуков OpenCode стал только для
чтения (см. [детали форматов, §8](PROVIDERS.ru.md)) — не по догадке, а по проверяемому факту.

У остальных девяти CLI написано «схемы нет». Это честный ответ, а не «всё в порядке»: выдуманный
адрес схемы либо тихо провалится, либо сверит панель с чужим файлом и выдаст ложное «всё сходится».
Опубликуют схему — она появится в реестре `domains/format-check.ts` вместе со списком ключей.

Сеть трогается не чаще раза в неделю и никогда на вашем пути: раздел открывается по кэшу
(`claude-control/format-check.json`), устаревший результат обновляется фоном, и даже полный отказ
сети даёт `не проверено` у одного провайдера, а не ошибку панели. Кнопка «Проверить сейчас» —
единственное место, где ответ ждёт сеть.

## 7. Свой эндпоинт

Агентный CLI ходит в модель по адресу, и адрес можно поменять — на модель в своём контуре, на
шлюз компании или на прокси. Делается это переменными окружения, у каждого CLI своими:
`ANTHROPIC_BASE_URL`, `GOOGLE_GEMINI_BASE_URL`, `OPENAI_BASE_URL`, `AIDER_OPENAI_API_BASE`.
Карточка «Свой эндпоинт» в настройках заводит профиль один раз — адрес, вид API, модель — и
раскладывает его по нужным переменным выбранного CLI одной кнопкой.

Вид API — это схема, по которой эндпоинт принимает запросы, и выбирается он по эндпоинту, а не по
CLI: одна и та же локальная модель часто отвечает сразу в нескольких схемах.

| Вид API         | Кому подходит                                                                       |
| --------------- | ----------------------------------------------------------------------------------- |
| `openai-compat` | llama.cpp, vLLM, Ollama, LM Studio, корпоративные шлюзы — почти все умеют эту схему |
| `anthropic`     | прокси или шлюз на схеме Anthropic; единственный вид, который принимает Claude Code |
| `google`        | шлюз на схеме Gemini                                                                |

Кнопка «Проверить связь» спрашивает у адреса **список моделей** (`/v1/models`, `/v1beta/models`
или `/models` — по виду API) и ничего не генерирует: проверка бесплатна и токенов не тратит. Если
список пришёл, поле модели становится выпадающим с тем, что на этом адресе действительно есть.
Пробный ответ модели — это уже чат, отдельное и платное действие.

Профиль принимают четыре CLI — те, у которых переменная адреса задокументирована:

| CLI         | Куда пишется                                                                                 |
| ----------- | -------------------------------------------------------------------------------------------- |
| Claude Code | `~/.claude/settings.json` → `env`: `ANTHROPIC_BASE_URL`, `ANTHROPIC_MODEL`                   |
| Gemini CLI  | `~/.gemini/.env`: `GOOGLE_GEMINI_BASE_URL`, `GEMINI_MODEL` (только `https`, кроме localhost) |
| Qwen Code   | `~/.qwen/.env`: тройка `OPENAI_*` либо `ANTHROPIC_*` — Qwen принимает оба вида               |
| Aider       | `~/.aider.conf.yml` → `set-env`: `AIDER_OPENAI_API_BASE`, `AIDER_MODEL`                      |

У Codex и Continue адрес модели задаётся только в конфигурационном файле руками (`model_providers`
в `config.toml` и `apiBase` у каждой модели в `config.yaml`); переменной окружения для него не
задокументировано, и панель её не выдумывает — строка так и говорит. У Goose, Kimi Code, Cursor и
OpenCode своего раздела переменных окружения нет вовсе.

Отдельным выбором в той же карточке профиль назначается **встроенному ассистенту панели** —
тому, что заполняет формы. Он ничего не записывает: панель ходит по адресу напрямую, минуя и
облако, и CLI провайдера. Переключается он отдельно от CLI намеренно: подсказки в формах и работа
агента — разные задачи.

**Токен по умолчанию не попадает в чужой конфиг.** Он хранится зашифрованно в панели
(`provider-keys.enc`, AES-256-GCM) и используется при проверке связи и ассистентом; наружу отдаётся
только маска. В файл CLI он уйдёт открытым текстом, если поставить галочку «писать токен в
конфигурацию CLI» — своего хранилища секретов у чужих CLI нет, и это осознанный шаг с
предупреждением. Без галочки в файл уходят только адрес и модель.

Запись идёт как любая другая правка конфигурации: резервная копия, атомарная запись, свои значения
пользователя рядом сохраняются. Уже запущенная сессия CLI об изменении не узнает — переменные
читаются при старте.

Свой адрес отвечает на вопрос, КУДА уходит запрос, но не смотрит, ЧТО в нём: если по адресу стоит
внешний шлюз, данные всё равно покидают контур. Подмена имён и телефонов внутри запроса — отдельная
задача, профилем она не решается.

## 8. Защита данных (локальный прокси)

Свой адрес решает, КУДА уходит запрос. Раздел «Защита данных» решает, ЧТО в нём уходит — и работает
с любым адресом, включая облако вендора.

Панель поднимает слушатель на `127.0.0.1` (по умолчанию порт 5179) и пересылает запросы наверх сама.
Если указать CLI этот адрес вместо адреса модели, панель видит **тело** каждого запроса: промпт,
содержимое прочитанных агентом файлов, вывод инструментов, аргументы вызовов. Это принципиально
больше, чем видит хук на промпте.

TLS при этом не вскрывается: CLI обращается к прокси по `http` на локальный адрес, а наверх прокси
идёт обычным `https`-клиентом. Подменных сертификатов и доверенных корневых не требуется — вся
настройка сводится к смене одного адреса, проще всего профилем эндпоинта из §7.

### Правила

| Вид                | Что ищет                                                                                                                                        |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| встроенный образец | почта, телефон, ИНН, СНИЛС, номер карты, секретные ключи; где у формата есть контрольная сумма — она проверяется                                |
| свой словарь       | список значений (ФИО, названия проектов, адреса): без учёта регистра, целыми словами, с русскими окончаниями — «Урманова» найдётся по «Урманов» |
| своё выражение     | регулярное выражение; разбирается до сохранения                                                                                                 |

Контрольные суммы важнее, чем кажется: без них правило ИНН ловило бы любое одиннадцатизначное число,
а ложное срабатывание в защите данных хуже пропуска — оно ломает работу и учит выключать защиту.

Действий три. `mask` заменяет значение меткой `[ИМЯ_1]` и **возвращает его обратно в ответе модели**
— включая потоковый ответ, где метка разорвана между кадрами. `block` останавливает запрос целиком и
отдаёт CLI отказ в форме его же API. `flag` ничего не меняет и только пишет в журнал — режим обкатки
нового правила.

### Что разбирается

| Путь                | Что панель правит                                                                                     |
| ------------------- | ----------------------------------------------------------------------------------------------------- |
| `/v1/messages`      | `system`, тексты сообщений, результаты инструментов, строковые аргументы вызовов                      |
| `/chat/completions` | содержимое сообщений и аргументы вызовов функций (любой OpenAI-совместимый шлюз)                      |
| всё остальное       | не разбирается — по умолчанию **отклоняется** (сюда попадает и Gemini: его форму панель не разбирает) |

Блоки размышления Anthropic не трогаются никогда: у них есть подпись, и правка сломала бы ответ.

### Границы

Прокси находит ровно то, что описано правилами: незаписанную фамилию он не угадает, а обратная
подстановка работает по точному совпадению — если модель перефразирует метку в ответе, подставлять
будет некуда, и человек увидит `[ИМЯ_1]`. Слушатель не публикуется наружу ни при какой настройке:
он видит расшифрованные запросы вместе с ключами. В журнале нет значений — только правило, метка и
счётчик.

Правила лежат в `<каталог конфигурации>/claude-control/dlp-rules.json`, отдельно от `state.json`: в
их словарях стоят настоящие фамилии и телефоны, а настройки панели переносятся между машинами
экспортом. Словарь меток живёт только в памяти и на диск не пишется.

## 9. Гейт на промпте (хук)

Третий механизм, самый простой и самый ограниченный: панель кладёт в каталог хуков конфигурации
скрипт `claude-control-prompt-gate.mjs` и прописывает его в `settings.json` событием
`UserPromptSubmit`. Прокси из §8 для этого поднимать не нужно; правила берутся из того же
`dlp-rules.json` — второго словаря нет.

Гейт видит **только то, что человек отправил из строки ввода**. Файлы, прочитанные агентом, вывод
команд, результаты инструментов, промпты подагентов проходят мимо него — это видит прокси.

Действий два: отклонить промпт или предупредить и отправить. Заменить текст меткой гейт не может:
событие `UserPromptSubmit` не позволяет подменить промпт. Это ограничение Claude Code, а не панели.
Правило, у которого собственное действие — `block`, останавливает промпт даже при общей настройке
«предупредить»: иначе она молча понижала бы запрет до уведомления.

| Ситуация                            | Что делает скрипт                                                    |
| ----------------------------------- | -------------------------------------------------------------------- |
| совпадений нет                      | выходит с кодом 0 молча                                              |
| совпадение, действие «отклонить»    | пишет в stderr **названия правил** (не значения) и выходит с кодом 2 |
| совпадение, действие «предупредить» | отдаёт `systemMessage` и пропускает промпт                           |
| файл правил не читается             | пропускает промпт и сообщает, что он **не проверен**                 |
| форма входных данных незнакома      | то же самое: сомнение — не повод блокировать работу                  |

Скрипт самодостаточен: логика поиска вставляется в него при установке, поэтому он работает и когда
панель закрыта. Словаря внутри него нет — правила читаются с диска при каждом срабатывании, иначе
файл хука уносил бы персональные данные вместе с переносом окружения. Скрипт, изменённый руками,
панель не перезаписывает и не удаляет: об этом сообщает раздел, а возврат своей версии — отдельная
кнопка.

Обходится гейт тривиально — тот же смысл, пересказанный другими словами, он не поймает. Это заслон
от случайной вставки чужих данных в промпт, а не от человека, который хочет их отправить. Настоящий
контроль содержимого — это §8.
