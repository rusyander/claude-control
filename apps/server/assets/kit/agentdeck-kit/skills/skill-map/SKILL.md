# Skill map — flows, not a list

The `skill-hint` hook names ≤2 skills on a clear match and defers here past that: pick by the
**next step**, not the topic.

**First gate — does any skill earn its place?** Mechanical, clearly-scoped work → act directly; skills
are for ambiguous, risky or user-visible work. "just do it" / "no ceremony" from the user → minimum.

## Main flow: task → MR

1. **Unfamiliar project** (no profile / CLAUDE.md / memory) → `agentdeck-kit:project-onboard`: materializes
   `.claude/project-profile.md` before refactor/audit/tests.
2. **The task itself is unclear** — two readings, a gap it never covers, a subject unlocatable after
   searching → `agentdeck-kit:requirements-grilling`: rounds over the decision tree, a recommendation per question.
   Clear → skip.
3. **A raw batch of tasks or bugs arrives** (screenshots, review remarks — each verified against the
   code first) → `agentdeck-kit:task-spec-builder` → `TASKS.md` with where-in-code, acceptance criteria, verification.
   One unambiguous task → skip.
4. **Edits.** User-visible change → before/after screenshots per the kit rules, no reminder needed.
5. **Lock the fix in** → `agentdeck-kit:bug-regression-test` (`mustfail` RED on the pre-fix tree); broader coverage →
   `agentdeck-kit:unit-integration-tests` (each test proven by a killed mutant), full flows only → `agentdeck-kit:playwright-e2e-tests`.
6. **Ready to hand over** → `agentdeck-kit:prepare-mr`, the gate that chains the rest: full verification →
   `agentdeck-kit:style-conformance-review` → pre-MR sieves with evidence (unchecked sieve = not ready; the push-sieves
   hook on the agent's own pushes is the mechanical backstop) → readiness checklist → `agentdeck-kit:changelog-builder` for the description;
   UI change → `agentdeck-kit:mr-visual-report` (before/after per page, QA steps + test data on top).

**A whole ticket handed over** ("do task X", "take it") runs all of this as one fixed
conveyor instead → `agentdeck-kit:ticket-delivery`: claim, branch, shots, fix, discovered gates, draft MR,
two-agent review, live run, finish. It subsumes steps 4–6 and `agentdeck-kit:prepare-mr`; a project's own ticket skill takes
precedence.

## On-ramps

- **The stand is sick** (won't start, 500/502, broken login, dead after rebuild) → `agentdeck-kit:stand-doctor`:
  services and logs before code.
- **Any bug** — a log/stacktrace error, wrong behaviour, a flaky test → `agentdeck-kit:log-forensics`: no theory
  before a red-capable loop, three failed fixes → question the architecture; ends in a fix (step 5) or
  a backend report.
- **Any code to review** — MR, branch, directory, whole repo → `agentdeck-kit:deep-review`: findings proved by a run
  or `file:line`, second entry from the contract (docs/API vs stand, `axis-2.md` §h), report in
  `.agent/reviews/`, forge inline on request; floors
  `deep-review/references/{backend,frontend,data-deploy}.md`, proof ladder L0–L4 `live-proof.md`;
  tools `review-plan` (lanes, rounds, ledger) · `review-sweep` · `review-harness` (L3 stand) ·
  `review-eval` (regression set, `eval.md`). "what did they answer on the review", or the author has replied →
  `node <kit>/tools/review-sync.mjs <report> [--write]` (`--all` = calibration). Own _just-made_
  fixes: correctness → the six classes of `deep-review/references/axis-1.md` (siblings + parity at
  minimum); style → `agentdeck-kit:style-conformance-review`.
- **A live check on the stand** → no skill: the `live-check` situational rule arrives when a stand
  or browser run starts; depth and entry points from `node <kit>/tools/risk-tier.mjs`. Stand down →
  `agentdeck-kit:stand-doctor`.
- **A design or UX question code has to answer** ("which layout?") → `agentdeck-kit:prototype`: throwaway variants,
  a decision, deleted — never promoted.
- **A merge or rebase stuck on conflicts** → `agentdeck-kit:resolving-merge-conflicts`: resolve by intent, verify,
  one approved git op at a time; aborting is the user's call.
- **A Figma design to match** → `agentdeck-kit:figma-parity`; also fired by a Figma link via `figma-hint`.
- **A draw.io schema wanted** — diagram from code or a spec, or editing a `.drawio` → `agentdeck-kit:drawio-architect`:
  information-sheet shape, generated by `generate.mjs`, gated at `--strict`.
- **"It's slow"** → `agentdeck-kit:perf-audit`: measure first (bundle, network, renders, timings), then fix.
- **Untranslated UI text or locale drift** → `agentdeck-kit:i18n-audit` (drift gate `tools/i18n-keydiff.mjs`, plural-aware).
- **Accessibility asked for** (keyboard, contrast, aria) → `agentdeck-kit:a11y-audit`.
- **Frontend types disagree with the API** → `agentdeck-kit:api-contract-sync`: frontend fixed, backend read-only.
- **A batch of same-shaped units** ("in every file", "en masse", migration sweeps) → `agentdeck-kit:batch-runner`:
  one bounded-context worker per unit, ≥8 homogeneous units, else direct.

## Codebase health — upkeep, not feature work

- `agentdeck-kit:project-audit` — whole-repo HARD audit ("full / hard audit"): tool sweep + stack-canon review,
  verified findings → report pack in `.agent/audit/<date>/`.
- `agentdeck-kit:refactor-code-health` — dead code, duplication, simplification. Audit first, apply on approval.
- `agentdeck-kit:improve-react` — whole-codebase React audit, read-only (scan `--no-score`, plans in `.agent/react-plans/`, fan-out/execute only on a go-ahead), plans someone else executes. React
  questions (hooks, renders, context) come here; general health → `agentdeck-kit:refactor-code-health`.
- `agentdeck-kit:dependency-risk-review` — before adding a **new** package; `agentdeck-kit:deps-upgrade` — upgrading existing.
- `agentdeck-kit:storybook-stories` — component state coverage; play functions that assert, and a gate that runs them.

## Documentation

- `agentdeck-kit:doc-hygiene` — any agent-facing doc (CLAUDE.md, `.agent/`, memory, project-profile, TASKS.md), or a
  doc-guard hook fired; also owns `.agent/glossary.md`, the domain vocabulary.
- `agentdeck-kit:human-docs` — README, `docs/`, guides, ADR. **User-invoked only**: type `/agentdeck-kit:human-docs`.
- `agentdeck-kit:docs-triage` — all project documentation in one pass, both halves; routed by `docs-order-hint` on
  "put the docs in order".

## Underneath — vocabulary and operations

For when the _discipline_, not the task, is the problem; the skills above pull them in.

- `agentdeck-kit:style-conformance-review` — the project style profile in project memory, learned from review
  remarks (`node <kit>/tools/review-harvest.mjs` pulls them from the forge through `glab`) and feedback memories;
  loaded before the first edit, one self-review per finished batch; `agentdeck-kit:deep-review` and
  `agentdeck-kit:refactor-code-health` read it.
- `agentdeck-kit:frontend-architecture` — React/TS doctrine, opt-in per project via a project-profile binding; the
  project idiom outranks it EXCEPT invariants 9/10 (`colocation.md` / `styles.md`), which no idiom waives. Cross-file gate: `node <kit>/tools/fe-arch-check.mjs <src>`.
- `agentdeck-kit:token-economy` — multi-step work, subagents, bloating context: subagent I/O contract, tiered
  verification, model tiering.
- `agentdeck-kit:skill-authoring` — writing, editing or auditing a skill: invocation axis, information ladder, pruning
  verdicts.
- `agentdeck-kit:config-draft` — changing the agent config layer (rule, hook, skill, instruction file): which layer
  carries the meaning, draft → gate → English final → gate → proved write. Routed by `skill-hint`.

## Keeping this honest
