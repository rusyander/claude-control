# Контур: корпоративная платформа по одному ключу

Контур — это платформа компании, к которой панель ходит по корпоративному ключу: её модели,
эмбеддинги и агенты. Ключ остаётся в панели, а агентные CLI направляются на её локальный шлюз —
иначе корпоративный ключ пришлось бы разложить по конфигурациям девяти CLI, откуда его уже не
забрать.

Этот документ — обзор для человека: что контур даёт, чего он не даёт и почему. Подробности с
картинками живут в самой панели: **Справка → Контур** (там же четыре диаграммы, таблица отказов и
список подписанных компромиссов, который печатается из реестра, а не переписывается руками).

## Агентный CLI: как он работает через контур и чего это стоит

Поле с инструментами клиента публичная схема платформы не принимает: набор собирает сама платформа —
по модели, скиллу и владельцу ключа — и исполняет его на своей стороне, а присланный список
отбрасывается как лишний ключ. Это не меняется и меняться не будет.

Панель обходит это прослойкой, включённой по умолчанию: правила протокола и схемы инструментов
вашего CLI уезжают наверх ТЕКСТОМ внутри системной строки, а вызов панель собирает обратно из ответа
модели и отдаёт CLI настоящим блоком вызова. Агент правит файлы, видит свои MCP-серверы, а результат
работы инструмента уезжает наверх тем же текстом протокола — иначе модель не помнит ни своего
вызова, ни его ответа.

Это протокол поверх чужого, и он слабее вендорного — вот всё, что за это платится:

- **Идентификаторов вызова нет, параллельных вызовов одним ходом не бывает.** Агент идёт по одному
  шагу за ход.
- **Выполняется не всё, что похоже на вызов.** Только блок в тегах протокола и ответ, который
  ЦЕЛИКОМ состоит из одного вызова. Вызов, показанный примером внутри блока кода, не выполняется
  никогда, даже верный: так же выглядят и цитата протокола, и файл документации, который агент
  только что прочитал и показал. Неразобранный блок остаётся в ответе текстом, а в следе запроса
  написано, почему.
- **Схемы едут заново каждым ходом** — кэша промпта у контура нет. Замерено на настоящих прогонах:
  24 инструмента — около 58 тысяч знаков системного текста и 86 КБ запроса на ход; интерактивный
  прогон с полным промптом CLI давал 108 546 знаков и 154 КБ. Поэтому прогон через контур по
  умолчанию идёт с коротким промптом панели, а не с промптом CLI.
- **Послушается ли модель — её дело.** Слабая модель опишет действие словами вместо вызова: ход
  кончится удачно, а файла не будет. Такой ход панель помечает на карточке «Инструменты через
  контур» — это пометка по словам ответа, а не приговор.

Прослойка выключается на самом контуре. Выключенная, она возвращает прежнее поведение: через контур
CLI разговаривает, но файлов не правит, — и работать агентом он продолжает по своему обычному ключу.

## Где живёт ключ

Ключ вводится один раз в мастере и дальше живёт только на этой машине:

- в отдельном файле хранилища ключей внутри рабочего каталога панели, зашифрованным (AES-256-GCM,
  парольная фраза — машинно-локальный секрет в соседнем файле с правами только для владельца);
- в `state.json`, в резервных копиях настроек и в переносе среды его нет;
- в конфигурацию CLI уходит адрес локального шлюза и заглушка вместо ключа
  (`panel-contour-no-key-needed`); настоящий ключ подставляет шлюз в момент запроса;
- в ответах панели ключ всегда маска вида «первые знаки… последние четыре».

Цена этого решения названа честно: **пока панель выключена, шлюз закрыт**, и направленный на него
CLI получит отказ соединения — а не тихо уйдёт в облако вендора. Это выбор в пользу предсказуемости:
корпоративный запрос, ушедший не туда, хуже любого отказа.

## Отказы, которые вы увидите

| Код | Что значит                                                                                    |
| --- | --------------------------------------------------------------------------------------------- |
| 401 | Ключ не приняли. Причин пять, и контур их не различает: ключ неизвестен или отозван, истёк,   |
|     | исчерпал бюджет, владельца удалили, сверка владельца не удалась. Панель называет все пять.    |
| 402 | Лимит расхода — пользователя, команды или инстанса. Это НЕ бюджет ключа.                      |
| 403 | Ключу не разрешена запрошенная модель; её имя есть в тексте отказа.                           |
| 404 | Либо модель убрали из контура, либо адрес указывает не на публичный API. Названы оба чтения.  |
| 429 | Слишком часто. Панель повторяет ровно один раз и говорит, через сколько повторять вам.        |
| 451 | Проверки содержимого компании остановили запрос. Названия проверок видны, текста запроса нет. |

## Как отключить

Три разных действия, от самого мягкого:

1. **«Снять применение»** — файлы CLI возвращаются к прежним значениям, управляемый профиль
   исчезает. Контур остаётся подключённым.
2. **Выключить тумблер контура** — шлюз перестаёт его обслуживать. Настройка, ключ и история
   расхода остаются.
3. **«Удалить контур»** — уходят настройка, ключ и след проверки; применение снимается
   автоматически.

Копии «до» всех правок конфигураций лежат в разделе «История» и переживают удаление контура.

## Что панель про контур НЕ делает

- Не меняет ничего на стороне контура: ни гардрейлы, ни инструменты, ни лимиты — они настраиваются в
  админке компании.
- Не обещает возможностей, которых не проверила пробой: неподтверждённое показывается словами «не
  объявлено», а не галкой.
- Не сливает расход контура с аналитикой транскриптов: это две разные величины, и наша — оценка по
  нашему справочнику цен, помеченная знаком «≈».

## Чего мы просим у команды платформы

Часть ограничений выше — не наш выбор, а свойство чужой платформы: панель их обходит и называет
вслух карточками «компромисс». Что именно мы просим опубликовать, чтобы эти обходы стали не нужны,
и какие вопросы у нас остались без ответа — одной страницей:
[docs/PLATFORM-ЗАПРОС.ru.md](PLATFORM-ЗАПРОС.ru.md). Ни одна строка оттуда не держит работу панели:
всё уже работает на сегодняшней платформе.
