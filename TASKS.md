Замер 16.10: четыре группы разделения, ~3 часа, Opus 5.5 с усилием high. ~1150 вызовов, чтение
кеша 196 млн токенов, запись 2,4 млн, вывод 0,69 млн. Ревьюеры добавили ~23 млн, родительский чат —

формула: расход ≈ вызовы × (постоянная часть + накопленное) + новый текст по цене записи + вывод.
Сейчас постоянная часть — 75–77 тыс. токенов (~45 % каждого вызова), средний контекст ~170 тыс.,
сжатие — на ~260 тыс., по два раза в чате. По видам шагов: чтение и поиск — 22 %, снимки — 17 %,
гейты и тесты — 15 %, правки — 10 %, git — 7 %, трекер и MR — 5 %. План идёт по рычагам формулы.
Цель — вдвое меньше на ту же работу при тех же моделях, усилии, гейтах, ревью и снимках.

Правила работ:

- Сначала измеритель, потом правки. Каждый пункт закрывается замером до/после на таком же
  прогоне и тестом на сам механизм.
- Качество не платит. Ни одна проверка, ревью или снимок не убирается. Если урезанное
  понадобилось агенту, он получает это сам, без отказа и без лишнего хода.
- Общее для всех провайдеров делается на стороне панели: задание, набор MCP, инструкции, вывод
  команд, очередь шагов. Так оно действует на Claude, Codex и Qwen сразу; особенности провайдера
  идут отдельными пунктами.

### Этап 9. Локальная память задачи — быстрее и точнее, для любого CLI

Токены экономятся, только когда модель читает меньше. Поэтому всё здесь отдаёт агенту короткий
точный ответ вместо пролистывания. Данные лежат в копии задачи (`.agent/run/`) и уходят вместе с
копией, когда задача закрыта. Всё делается командами и MCP панели, а не возможностями одного CLI,
поэтому работает у Claude и Codex сразу, дальше — у остальных.

- **9.1 Индекс кода проекта.** Карта символов: где объявлено, где вызывается, кто импортирует.
  Строится один раз, обновляется по изменённым файлам и отвечает одной строкой на «где
  используется X» вместо `grep` по репозиторию и чтения десятка файлов. Ответ точнее поиска по
  тексту, так что качество выше. Для Claude дополнительно проверить его встроенный инструмент
  LSP.
- **9.4 Общий стенд и кеши сборки на разделение.** Один прогретый dev-сервер и общий кеш тестов на
  все группы вместо четырёх отдельных. Это скорость и нагрузка машины, а значит — меньше таймаутов
  и повторных гейтов (3.2).
- **9.5 Данные трекера один раз.** Разбор при разделении уже читает задачи, а группы потом
  перечитывают их снова. Панель кладёт текст задач группы в её копию, и в трекер группа ходит
  только за изменениями.

## Живая приёмка переноса среды — по пункту на каждый CLI

Третий этаж доктрины проверок (§8 [docs/PORTABILITY-DESIGN.ru.md](docs/PORTABILITY-DESIGN.ru.md)): круговой тест
доказывает формат, поддельный CLI на `PATH` — что до процесса доехало задуманное, и только
настоящий CLI отвечает на вопрос «ведёт ли он себя так же». Поэтому пункт ниже **закрывается
прогоном настоящего CLI, а не тестом на заглушке**, и до тех пор отчёт верности честно помечает
провайдера непроверенным. Где приёмка уже пройдена — таблица §8.1
[docs/PORTABILITY-DESIGN.ru.md](docs/PORTABILITY-DESIGN.ru.md); здесь только открытые.

Ожидаемый исход каждой пробы не переписан сюда намеренно: его показывает сама панель — отчёт
верности на экране переноса называет уровень и причину до применения. Проба пройдена, если поведение
совпало с обещанным уровнем, **включая честный отказ**: `×` с причиной — это пройденная проба, а
молчание — нет.

- **Kimi Code** (`kimi`). Пробы: хук блокирует · скилл срабатывает · право отказывает ·
  MCP-инструмент виден · переменная дошла · команда развернулась. Особое: блокировать умеют только
  три события, остальные наблюдательные — блокирующий `PostToolUse` обязан деградировать вслух;
  раздел плагинов read-only, панель его показывает и не пишет.
- **Cursor** (`cursor`). Пробы: хук блокирует · скилл срабатывает · право отказывает ·
  MCP-инструмент виден · переменная дошла · команда развернулась. Особое: панель его не запускает
  (`cliRunnable: false`), поэтому эмуляции у него нет ни в одной строке — половина проб обязана быть
  честным `×` с причиной, и проверяется именно это, а не «а вдруг заработает».
