# Claude Control — прогресс

Обновлено: 19.07.2026. Проект не под git (репозиторий не инициализирован).

## Что готово и проверено

- **9 форм с чат-помощником**: правила, скиллы, хуки, скрипты, MCP, права, переменные, группы,
  сценарии. Прогон `node tools/qa/check-all-forms.mjs` — все девять открываются, помощник на месте.
- **Страница «Скрипты»** (`/scripts`): список файлов из `~/.claude/hooks`, признак привязки к хуку,
  редактор кода с помощником, создание и удаление. Цикл создание→правка→удаление проверен через API,
  за собой убрано (в hooks/ снова 8 файлов).
- **Плагины**: найдена и исправлена поломка каталога — CLI отдаёт `{installed, available}` с полями
  `pluginId`/`marketplaceName`, а парсер ждал массив с `id`. Теперь каталог из 260 плагинов
  с поиском и сортировкой по популярности. Цикл установки/выключения/удаления проверен на
  `claude-md-management` — состояние вернулось к исходным 10 плагинам.
- **Аналитика, обзор, правила, скиллы, хуки, MCP, права, переменные, группы, настройки, справка** —
  сделаны ранее.

## Чат (в работе) — серверная часть готова

Файлы: `apps/server/src/domains/chat/`, `apps/server/src/routes/chat-routes.ts`,
`packages/contracts/src/chat.ts`.

- `GET /api/chats` — 129 чатов, первый проход 1 с, кеш по mtime 33 мс.
- `GET /api/chats/:id/messages` — потоковое чтение, файл 117 МБ за 1 с, в памяти последние 400.
- `POST /api/chat/send` — SSE-поток: `session`, `text` (посимвольно), `thinking`, `tool`, `limit`,
  `done` со стоимостью. Проверено сквозняком.
- `POST /api/chat/:id/stop`, артефакты и вложения — готовы.

### Что выяснено о Claude Code (проверено на практике)

- Стриминг: `claude -p --output-format stream-json --verbose --include-partial-messages`.
- Заголовки чатов лежат в транскрипте как `type: "ai-title"` (последнее вхождение);
  есть лишь у ~19% сессий — нужен фолбэк на первую осмысленную реплику.
- `--name` задаёт имя сессии, `--fork-session` ветвит диалог (для правки сообщения),
  `--resume <id>` продолжает.
- **Лимиты подписки доступны локально**: событие `rate_limit_event` в потоке —
  `five_hour`, `resetsAt`, `status`. Раньше считалось, что их не получить.
- Артефакты: с `--permission-mode acceptEdits` Claude пишет файлы в рабочую папку — проверено.
- Список чатов строить только по `<projectDir>/<sessionId>.jsonl`, вложенные `subagents/` пропускать.
- Фильтр реплик: `type` user/assistant, без `isMeta`, `isCompactSummary`, `isApiErrorMessage`
  и без `toolUseResult`.

### Решения по чату (согласованы с пользователем)

1. В списке — **все** чаты Claude Code из `~/.claude/projects`.
2. Библиотеки для превью ставить можно: **markdown-it + shiki** (уже установлены).
3. Рабочая папка — **песочница** `claude-control/chats/<id>/`, артефакты не мешаются с проектами.

### Фронт чата — готов и проверен

Файлы: `entities/Chat/` (API + `useChatStream`), `features/ChatList`, `features/ChatMessages`,
`features/ChatComposer`, `features/ArtifactPreview`, `pages/Chat/`.
Прогон: `node tools/qa/check-chat.mjs` — реальный разговор, два созданных файла,
страница отрисована во врезке, ошибок консоли нет. Проверено в обеих темах.

Работает: список из 138 чатов с поиском, лента со схлопнутыми инструментами и размышлениями,
посимвольный стриминг с курсором, отмена, голосовой ввод, вложения (перетаскиванием и кнопкой),
предпросмотр артефактов с вкладками «превью / исходник» (страница в песочном iframe, разметка,
код с подсветкой Shiki, картинки, PDF), копирование и правка своих сообщений,
показ стоимости запроса и времени сброса лимитов.

### Три дефекта, найденных прогонами (исправлены)

1. **Папка чата была внутри `.claude`** — Claude Code защищает свой каталог, запись артефактов
   блокировалась. Перенесено в `~/.claude-control/chats/`.
2. **Обрыв разговора на старте** — слушали закрытие запроса, а оно наступает сразу после
   дочитывания тела. Теперь слушаем закрытие ответа.
3. **Артефакты терялись при первом ответе** — папка звалась по временному id, а чат получал
   sessionId. Теперь папка переезжает под sessionId после завершения.
4. **Ответ дублировался** — поток и перечитанная история показывались одновременно.
5. **Несуществующие токены стилей** (`--color-accent-soft`, `--font-size-md`, `--transition-fast`
   и другие) — в проекте они называются иначе; сверено со `shared/styles/global.scss`.

## Песочница — готова и проверена

Файлы: `apps/server/src/domains/sandbox/` (`SandboxConfig`, `HookProbe`, `McpProbe`),
`apps/server/src/routes/sandbox-routes.ts`, `apps/web/src/entities/Sandbox/`,
`apps/web/src/features/SandboxRunner/`. Прогон: `node tools/qa/check-sandbox.mjs`.

**Как устроена изоляция.** Claude Code читает настройки из каталога в `CLAUDE_CONFIG_DIR` —
песочница собирает временный каталог, куда кладёт только проверяемое. Замерено: в таком
запуске 30 инструментов вместо 165, ноль MCP-серверов, ни один сторонний хук не срабатывает.
Из настоящего каталога переносится единственный файл — `.credentials.json`, без него
Claude Code отвечает «Not logged in». Файл `.mcp-secrets.env` не копируется никогда.
Второй рубеж — запреты в песочных настройках: `~/.claude/**` закрыт на запись, токены — на чтение.
Скрипты хуков запускаются копиями внутри песочницы. Всё стирается при закрытии окна.

**Проверено на деле:** запрос «прочитай settings.json и запиши PROBE.txt в ~/.claude»
завершился отказом по обеим операциям, файл не создан.

**Три вида проверки:**

1. **Прогон событий** (хуки, скрипты) — без модели, 70–90 мс на случай. Девять заготовок:
   безобидная команда, `rm -rf`, `git push`, запись секрета, ключ-заготовка и другие.
2. **Стенд MCP** — поднимает сервер, показывает инструменты со схемами, вызывает выбранный
   и показывает настоящий ответ.
3. **Разговор** (правила, скиллы, группы) — единственный способ для того, что не запускается
   само. Подтверждено: правило про русский язык в песочнице заставило ответить по-русски
   на английский вопрос.

**Находки прогонов:** современные хуки сообщают решение не кодом выхода, а полем
`permissionDecision` в JSON (`deny`/`ask`/`allow`) — стенд понимает оба способа.
Заготовка с секретом сначала содержала слово «example», из-за чего страж её правильно
пропускал как плейсхолдер: проверять надо строкой, похожей на настоящий ключ.

Кнопка песочницы встроена в правила, скиллы, хуки, скрипты, MCP-серверы и группы.

## Как запускать

- Сервер: `apps/server` → `node --watch --experimental-strip-types src/index.ts`, порт 5178.
  Watch-родитель умирает вместе с воркером — если убить процесс, поднимать заново вручную.
- Фронт: `apps/web` → vite, порт 8888.
- Проверки: `npx tsc --noEmit` в `apps/web` и `apps/server`; QA-скрипты в `tools/qa/`.
