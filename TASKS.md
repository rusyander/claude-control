  текст ошибки или хвост вывода CLI либо с прошлого разбора прошло несколько часов. Заодно замерить
  цену одного настоящего разбора (токены): истории расхода нет, для замера наблюдатель включается на
  время с согласия владельца. Проверка: тест «повтор разобранного раздела не запускает разбор» и

## Живая приёмка переноса среды — по пункту на каждый CLI

Третий этаж доктрины проверок (§8 [docs/PORTABILITY-DESIGN.ru.md](docs/PORTABILITY-DESIGN.ru.md)): круговой тест
доказывает формат, поддельный CLI на `PATH` — что до процесса доехало задуманное, и только
настоящий CLI отвечает на вопрос «ведёт ли он себя так же». Поэтому пункт ниже **закрывается
прогоном настоящего CLI, а не тестом на заглушке**, и до тех пор отчёт верности честно помечает
провайдера непроверенным. Где приёмка уже пройдена — таблица §8.1
[docs/PORTABILITY-DESIGN.ru.md](docs/PORTABILITY-DESIGN.ru.md); здесь только открытые.

Ожидаемый исход каждой пробы не переписан сюда намеренно: его показывает сама панель — отчёт
верности на экране переноса называет уровень и причину до применения. Проба пройдена, если поведение
совпало с обещанным уровнем, **включая честный отказ**: `×` с причиной — это пройденная проба, а
молчание — нет.

- **Kimi Code** (`kimi`). Пробы: хук блокирует · скилл срабатывает · право отказывает ·
  MCP-инструмент виден · переменная дошла · команда развернулась. Особое: блокировать умеют только
  три события, остальные наблюдательные — блокирующий `PostToolUse` обязан деградировать вслух;
  раздел плагинов read-only, панель его показывает и не пишет.
- **Cursor** (`cursor`). Пробы: хук блокирует · скилл срабатывает · право отказывает ·
  MCP-инструмент виден · переменная дошла · команда развернулась. Особое: панель его не запускает
  (`cliRunnable: false`), поэтому эмуляции у него нет ни в одной строке — половина проб обязана быть
  честным `×` с причиной, и проверяется именно это, а не «а вдруг заработает».

## Нужны вы — в конце (владелец 11.10)

- **Локальная модель в настоящем VS Code — вместе (решено 10.10).** Вы включаете «Claude Code на
  этой модели», открываете новый чат Claude Code в VS Code и задаёте вопрос; агент по журналу шлюза
  подтверждает, что ответил Qwen; затем выключаете.
- **«Запустил и ушёл» — на следующей настоящей пачке задач (решено 10.10).** Вы запускаете
  разделение и говорите «запускаю»; агент наблюдает, считает, сколько раз панель вас отвлекла и
  почему, и исправляет лишние отвлечения.
- **Режим разработчика Windows — по желанию (13.10).** Глобальная настройка
  `worktree.symlinkDirectories: ["node_modules"]` уже стоит, но собственные копии Claude Code
  (`claude --worktree`) делают настоящую символьную ссылку, и Windows отказывает (`EPERM`). Включите
  «Параметры → Для разработчиков → Режим разработчика», и настройка заработает; копии панели от этого
  не зависят — у них junction.
- **A/B раннего сжатия групп (2.1, ветка `perf/token-economy`).** Рычаг готов и выключен: панель,
  запущенная с `AGENTDECK_GROUP_COMPACT_WINDOW=160k`, отдаёт каждой группе окно автосжатия 160 тыс.
  вместо ~267 тыс. Нужны две одинаковые пачки задач: одна без переменной, другая с ней. Сравнить
  `pnpm tokens` (чтение кеша, вызовы) и качество: гейты, находки ревью, полнота MR. Включать по
  умолчанию — только если качество не хуже. Тот же рычаг задаёт группам Codex порог
  `model_auto_compact_token_limit` (у Qwen Code порога в токенах нет — туда не едет). Сжатие между ходами панель не шлёт: замер 15–16.10
  показал 1–3 хода на рабочий чат, такое сжатие сработало бы не больше двух раз за чат.
- **Qwen Code без стартовой сводки — по желанию (6.3).** `model.skipStartupContext` убрал бы из
  начала запроса дату и дерево проекта, и кеш слота локальной модели не сбрасывался бы даже со сменой
  дня. Цена: модель не знает каталог и ОС, пока сама их не спросит. Сейчас начало и так стоит между
  ходами одного дня — включать стоит, только если локальная Qwen будет вести группы много дней подряд.
- **Широкий поиск — в помощника с коротким ответом (8.5), вместе с A/B 2.1.** Обзорный поиск
  («где используется X», «какие страницы задеты») группа отдаёт помощнику и получает короткий ответ;
  код, который правит или проверяет, читает сама. Это правило задания группы и навыка доставки, но
  глобальное правило запрещает запускать помощников без вашего согласия на задачу — решить, где
  граница. Проверка — средний контекст и число находок ревью на той же паре прогонов, что и 2.1.
