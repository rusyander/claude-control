# Контур: корпоративная платформа по одному ключу

Контур — это платформа компании, к которой панель ходит по корпоративному ключу: её модели,
эмбеддинги и агенты. Ключ остаётся в панели, а агентные CLI направляются на её локальный шлюз —
иначе корпоративный ключ пришлось бы разложить по конфигурациям девяти CLI, откуда его уже не
забрать.

Этот документ — обзор для человека: что контур даёт, чего он не даёт и почему. Подробности с
картинками живут в самой панели: **Справка → Контур** — весь путь в снимках обеих сторон (админка
компании и панель), четыре схемы, таблица отказов и список подписанных компромиссов, который
печатается из реестра, а не переписывается руками.

## Что через контур работает

| Что                                                            | Как                          |
| -------------------------------------------------------------- | ---------------------------- |
| Встроенный ассистент панели                                    | работает                     |
| Генерация тест-кейсов, разбор прогонов, переводы, суммаризация | работает                     |
| Аналитика и объяснения в панели                                | работает                     |
| Эмбеддинги для поиска                                          | работает                     |
| Вызов агента контура (со знаниями и инструментами компании)    | работает, где тип объявил    |
| Переходник MCP: ваш CLI зовёт модель контура как инструмент    | работает                     |
| Агентный CLI, правящий файлы                                   | через прослойку, с оговоркой |
| Картинка по описанию из чата                                   | растр — где модель объявлена |
| Презентация по теме из чата                                    | работает                     |

## Активный контур и пробный запрос

Контуров можно подключить несколько, но работа идёт ровно через один — **активный**. Новый контур
становится активным сразу, по кнопке «Готово» в мастере, а прежний гаснет; у остальных на карточке
написано «не активен» и стоит кнопка «Сделать активным». Переключение — одно действие: применения прежнего
контура снимаются (файлы CLI возвращаются к прежним значениям), его отметка гаснет, ключ, бюджет и
настройки остаются на месте.

Сразу после активации панель сама задаёт модели короткий вопрос — через свой локальный шлюз, тем же
путём и той же моделью, которыми пойдёт CLI в терминале (его модель, иначе модель контура, иначе первая
чатовая модель каталога — не эмбеддинг). Модель, израсходовавшая потолок ответа на размышления, названа
отдельно от молчащей. Зелёная строка под адресом (ответ, задержка, модель) доказывает весь путь, а
не только то, что контур жив. Красная активацию **не отменяет**: погашенный шлюз, кончившийся ключ и
молчащая модель лечатся в разных местах, и причина написана словами.

«Вернуть провайдер по умолчанию» снимает применения, гасит отметку и оставляет панель и CLI на их
обычном провайдере. Кнопка стоит на карточке контура и в «Настройки → Модели», в профиле эндпоинта,
который завёл сам контур, — это одно и то же действие.

## Типы контура: Платформа компании и пресеты шлюзов

Тип контура — это драйвер. Кода у панели два: Платформа компании со своими правилами и совместимый с OpenAI
шлюз. Остальные типы — **пресеты данными** поверх второго: LiteLLM, vLLM, Ollama, OpenRouter, Azure
OpenAI, DashScope, Together AI. Пресет не приносит своего разборщика, он только объявляет, что
сверено с документацией шлюза, и ссылка на неё видна в мастере:

| Объявление                  | Что меняет                                                                      | Кто объявил                                                              |
| --------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Родная ручка Anthropic      | клиент Anthropic идёт к `/v1/messages` шлюза, а не мостом в `/chat/completions` | LiteLLM, vLLM, Ollama, OpenRouter                                        |
| Поле размышлений            | куда в теле уходит «размышления: вкл/выкл»                                      | vLLM `chat_template_kwargs.enable_thinking`, DashScope `enable_thinking` |
| Заголовок ключа             | в каком заголовке едет ключ                                                     | Azure OpenAI — `api-key`                                                 |
| Ручка картинок              | отдельная дорога генерации в схеме OpenAI                                       | никто: у Together она просит байты в другом формате                      |
| Инструменты, усилие, предел | полем или прослойкой; отправлять ли усилие; сколько шлюз ждёт цельный ответ     | базы                                                                     |
| Потолок любого ответа       | через сколько шлюз или прокси рвёт соединение, поток тоже; обрыв на нём назван  | Платформа компании (120 с); прочим — человек, если его прокси режет по часам        |

Если ваш шлюз устроен иначе, чем объявил пресет, это говорится в блоке «Что умеет шлюз» под
адресом: «как у пресета», своё значение или «не объявлять». Сказанное хранится у контура полем
`manifest` и проверяется при сохранении: путь с `..` или служебное имя поля отвергаются с названием
поля. Запись, правленная руками, читается по полю — негодное поле значит «как у пресета», соседние
остаются. Смена типа у нового контура сбрасывает сказанное: оно было о прежнем шлюзе.

## Агентный CLI: как он работает через контур и чего это стоит

Поле с инструментами клиента публичная схема платформы не принимает: набор собирает сама платформа —
по модели, скиллу и владельцу ключа — и исполняет его на своей стороне, а присланный список
отбрасывается как лишний ключ. Это не меняется и меняться не будет.

Совместимого шлюза (`openai-compat`) это не касается: поле инструментов он принимает, и панель
передаёт ему инструменты CLI как есть — схемы полем `tools`, вызовы и результаты настоящими
сообщениями, без протокола текстом. Чем пойдут инструменты, решает манифест драйвера
(`clientTools: 'native' | 'shim'`), а не проверка по имени; умолчания прослойки и короткого промпта
новому контуру ставит тип при подключении, у сохранённого контура смена типа выбор человека не
переписывает.

У платформа компании панель обходит это прослойкой, включённой по умолчанию: правила протокола и схемы инструментов
вашего CLI уезжают наверх ТЕКСТОМ внутри системной строки, а вызов панель собирает обратно из ответа
модели и отдаёт CLI настоящим блоком вызова. Агент правит файлы, видит свои MCP-серверы, а результат
работы инструмента уезжает наверх тем же текстом протокола — иначе модель не помнит ни своего
вызова, ни его ответа.

Это протокол поверх чужого, и он слабее вендорного — вот всё, что за это платится:

- **Идентификаторов вызова нет, параллельных вызовов одним ходом не бывает.** Агент идёт по одному
  шагу за ход.
- **Выполняется не всё, что похоже на вызов.** Только блок в тегах протокола и ответ, который
  ЦЕЛИКОМ состоит из одного вызова. Вызов, показанный примером внутри блока кода, не выполняется
  никогда, даже верный: так же выглядят и цитата протокола, и файл документации, который агент
  только что прочитал и показал. Неразобранный блок остаётся в ответе текстом, а в следе запроса
  написано, почему.
- **Схемы едут заново каждым ходом** — кэша промпта у контура нет. Замерено на настоящих прогонах:
  24 инструмента — около 58 тысяч знаков системного текста и 86 КБ запроса на ход; интерактивный
  прогон с полным промптом CLI давал 108 546 знаков и 154 КБ. Поэтому прогон через контур по
  умолчанию идёт с коротким промптом панели, а не с промптом CLI.
- **Послушается ли модель — её дело.** Слабая модель опишет действие словами вместо вызова: ход
  кончится удачно, а файла не будет. Такой ход панель помечает на карточке «Инструменты через
  контур» — это пометка по словам ответа, а не приговор.

Прослойка выключается на карточке контура — в списке «Что контур делает с запросом», раздел «Наша
сторона». Выключенная, она возвращает прежнее поведение: через контур CLI разговаривает, но файлов не
правит, — и работать агентом он продолжает по своему обычному ключу. Там же видно, почему её иногда
нельзя включить: инструменты платформы и наша прослойка — взаимное исключение, и панель откажет в
сохранении, а не выключит одну сторону молча.

## Какой моделью пойдёт запрос и что с «глубиной продумывания»

Через контур модель выбирает контур, а не CLI. Имена вроде `sonnet` или `opus` — это имена вендора,
и корпоративная платформа их не знает: запрос с таким именем возвращает 403 «модель». Поэтому на
карточке контура есть три вещи:

- **модель по умолчанию** — из каталога самого контура (те, которыми можно вести разговор; модели для
  эмбеддингов и снятые с публикации не предлагаются). Ваш выбор сильнее каталога: если модель
  временно пропала из ответа контура, панель не подменит её молча другой;
- **своя модель на потребителя** — чат, группы разделения, агент тестов и чужие CLI могут идти
  разными. Ассистента панели и терминала в этом списке нет: они ходят записанным профилем, и модель у
  них ровно одна — та, что в профиле;
- **карта соответствия** — «`sonnet` у нас значит вот эту модель контура». Имя, которого нет ни в
  карте, ни в каталоге, заменяется моделью контура, и **замена написана прямо в шапке разговора**:
  метка с чужим именем читалась бы как «идём этой моделью», а идём мы другой.

Глубина продумывания (`reasoning_effort`) сегодняшней платформой не принимается — это её свойство, а
не наш выбор. Панель не отправляет её вовсе и говорит об этом подписью на карточке и меткой в шапке
разговора; у чужого CLI, который просит глубину сам, потеря названа в следе запроса. Просьба
добавить это поле — строка письма [docs/PLATFORM-ЗАПРОС.ru.md](PLATFORM-ЗАПРОС.ru.md).

## Что контур делает с запросом по дороге

Контур не просто передаёт запрос модели: он проверяет содержимое, подменяет данные, подмешивает
знания компании, сжимает длинную переписку. Часть этого панель задаёт полями запроса — они на
карточке «Правила контура»; остальное включает владелец контура у себя, и панель только называет это,
чтобы поведение не выглядело случайным. Чего контур о себе не объявил, там не появится: список
берётся из описания платформы, а не додумывается.

Чем распоряжается панель:

- **инструменты платформы** — имена из реестра контура, вы переписываете их из его админки: маршрута
  «покажи инструменты» у ключа нет, как и для агентов. Пусто — наверх уходит `tool_choice: "none"`,
  то есть панель просит контур своими инструментами не пользоваться: промолчать значило бы оставить
  выбор его умолчанию;
- **цикл вызовов платформы** — `loop` (контур сам ходит по кругу «вызов — результат» и отдаёт готовый
  ответ) или `single_turn` (вызов возвращается клиенту — панель переводит его в диалект вашего CLI,
  поэтому он доезжает и до клиента Anthropic). Потока в `single_turn` контур не принимает (400), поэтому
  такой ход панель отправляет наверх целиком: ваш CLI по-прежнему получает поток, но ответ приходит
  разом и подчиняется потолку контура в 120 с. Без имён инструментов режим никуда не отправляется;
- **пресет генерации** — именованный набор параметров на стороне контура; пусто — контур берёт своё
  умолчание;
- **размышления модели** — три состояния: «по умолчанию» (поле не отправляется, решает шаблон модели —
  reasoning-модель вроде Qwen3 при этом думает), «включить» и «выключить» (явное значение в
  `chat_template_kwargs.enable_thinking`). Платформа компании доносит его только до моделей на самохостед vLLM,
  остальным провайдерам поле не передаёт. Размышления наружу не уходят, в чате виден обычный ответ.

Взаимное исключение на всю матрицу ровно одно: **инструменты платформы против нашей прослойки
инструментов**. Наш набор едет текстом и собирается обратно из ответа, набор контура исполняет сам
контур, и на один ход их может быть только один — панель не даст включить оба: сохранение, которое
СОЗДАЁТ противоречие, получит отказ теми же словами, которыми написана строка матрицы. Молча выключить
одну из сторон за вас она тоже не станет: о таком решении вы узнали бы по замолчавшему агенту. Если
противоречие приехало готовым (развернули чужой архив — план разворота называет такой контур заранее),
контур не заперт: на карточке стоят две кнопки выхода, каждая выключает свою сторону.

Остальные три строки матрицы — не выбор из двух. Подмена данных контура и защита данных панели
складываются по порядку (наша маска накладывается первой и обратима, её метки другого вида, и контур их
не трогает; свои метки контур сам возвращает значениями прямо в потоке ответа, а карту подмены клиенту
API не отдаёт); в этой строке и в строке проверок содержимого панель помечает включённой только свою
половину — включил ли владелец контура своё, она не знает и узнаёт лишь по сработавшему кадру. Сжатие истории контуром против наших контрольных точек — предупреждение: после
сжатия продолжение разговора может не знать начала задачи. Проверки содержимого против гейта
промпта — просто факт: откажут оба и по разным спискам, и второй отказ не значит, что первый не
сработал.

## Что из нашего едет в прогон (наши слои)

Обратная сторона той же карточки, раздел «Наши слои в прогоне». Через контур запрос идёт без кэша
промпта, поэтому всё, что панель добавляет от себя, оплачивается заново на каждом ходе — и всё это
снимается галочками. Цена снятия названа прямо: агент работает без ваших правил, а по ответу этого не
видно.

- **Наши правила едут в прогон** — общий выключатель. Снят — не едет ни один слой, какими бы ни были
  галочки ниже: они становятся серыми, а не спорят с ним;
- **личные правила, хуки и права** — всё из `~/.claude` разом (правила `CLAUDE.md`, хуки, права,
  личные скиллы, личные MCP-серверы — вместе с переходником панели к инструментам контура, он живёт
  там же), флагом `--setting-sources project,local`. Порознь их не снять:
  у CLI это один источник настроек `user`. Вместе с правами перестают действовать и ваши запреты
  `deny`. Проектный `CLAUDE.md` и настройки репозитория ЭТОТ флаг не трогает — это правила задачи, а
  не наши;
- **скиллы** — флагом `--disable-slash-commands`, отдельной галочкой: встроенные скиллы уходят только
  так. Снимаются при этом ВСЕ скиллы, включая скиллы репозитория (`.claude/skills`): раздельного
  флага у CLI нет;
- **MCP-серверы** — флагом `--strict-mcp-config`, и снимаются ВСЕ: личные, проектные из `.mcp.json`
  репозитория и переходник панели к инструментам контура. То есть галочка уносит и инструменты самой
  задачи, а не только ваши личные серверы. Остаётся один брокер прав панели: он приезжает своим
  `--mcp-config`, и без него каждый запрос разрешения стал бы молчаливым отказом посреди работы
  агента;
- **дописка панели к системному промпту** (инициативы, разделение задачи, продолжение сессии) — флага
  у CLI для неё нет, снимает её сама панель.

Под галочками стоит строка с флагами, с которыми уйдёт прогон, — та самая, что попадёт в запуск. Если
в маршруте контура не отмечен ни один запуск Claude (ни чат, ни группы разделения, ни агент тестов),
строка тут же говорит, что получить эти флаги пока некому: терминал правит файлы конфигурации,
ассистент ходит профилем эндпоинта, а чужому CLI слои не выдаются вовсе. То же самое говорит шапка
чата до отправки сообщения — причём в разговоре, заведённом разделением, она спрашивает тем же
потребителем, которым пойдёт прогон («Группы разделения»), а не «Чатом». Что какой флаг уносит, замерено на настоящем CLI, а не
взято из справки по флагу: проверка `node tools/qa/check-run-layers.mjs` запускает панелью настоящий
`claude` против стаба и ищет метку каждого слоя в теле ушедшего запроса.

Трёх соседних настроек в этом разделе нет намеренно: гейт промпта — физически наш хук в
`~/.claude/settings.json` и уезжает вместе с личными настройками; защита данных слоем не считается
вовсе (её не разменивают на бюджет промпта); каскад моделей включается у проекта, а не у контура. И
галочки эти — про Claude: снимаются они его флагами, поэтому на чужой CLI, идущий через тот же контур,
не действуют.

## Картинки и презентации: файл собирает панель

В чате у поля ввода есть кнопка «Режим»: обычное сообщение агенту, картинка по описанию или
презентация по теме. Оба режима работают у любого CLI и без контура — меняется только то, кто рисует,
и это сказано подписью под пунктом до нажатия.

Растровую картинку просит **сама панель**, а не агент, и причина не в удобстве — переписка агента
лежит в файлах Claude Code, и панель в них не пишет ни строки. Поэтому у такой картинки свой запрос и
свой ответ: карточка в правом столбце разговора и файл в каталоге данных панели. В ленте разговора её
нет, и агент о ней не знает.

Растр рисует не всякий контур, и дорогу сервер выбирает один раз:

- **контур, который объявил рисование** — картинка приезжает частью обычного ответа модели. Запрос
  идёт через локальный шлюз панели, то есть виден в журнале. В расход ключа он попадает, только если
  контур прислал счёт: Платформа компании присылает картинку без него, поэтому в расходе ключа её нет (след
  запроса в API шлюза помечен `usageUnreported`, а не молчаливым нулём);
- **отдельная ручка изображений контура** — если контур объявил именно её;
- **ваш профиль эндпоинта** — когда в нём заполнено поле адреса генерации картинок. Адрес не
  угадывается из основного: угаданный дал бы отказ 404 после того, как вы уже описали картинку;
- **иначе рисует агент разговора** — кодом, то есть вектор, а не снимок. Рядом с пунктом названо,
  что отняло растр: контур такого не объявил, в каталоге ключа нет модели с генерацией, в профиле
  эндпоинта нет адреса, выключен шлюз или у этого вида API такой ручки нет вовсе. Заперт режим только
  тогда, когда рисовать некому совсем — ни разговора, ни контура, ни профиля.

Презентация у контура ни одной способности не спрашивает: модель диктует структуру слайдов обычным
запросом, а HTML, PPTX и PDF панель собирает у вас на машине. От контура зависят только
фотографические картинки слайдов — они идут той же растровой дорогой. Фразу вокруг структуры или
размышления `<think>` перед ней панель отбрасывает сама; ответ совсем без структуры называет словами
модели. В разговоре колоду диктует его агент, контур или свой эндпоинт — только вне разговора.

Границы названы честно: одна картинка за раз, потолок 8 МБ, на диске остаются последние сто файлов, а
галереи и истории картинок в панели нет — нужное сохраняйте кнопкой «Скачать» сразу. Своего текста для
режима ждёт карточка «Картинка» в разделе «Промпты»; он уезжает системным сообщением только на дороге
«частью ответа» — у отдельной ручки изображений системного сообщения не бывает, и панель об этом
пишет прямо в меню.

Часть снимков справки про прослойку, картинки и красный пробный запрос снята на сценарном контуре —
заглушке, которая отвечает заранее заданным: у стенда компании нет рисующей модели, а маленькая
модель не делает вызовов инструментов стабильно. Такие кадры подписаны в справке прямо.

## Где живёт ключ

Ключ вводится один раз в мастере и дальше живёт только на этой машине:

- в отдельном файле хранилища ключей внутри рабочего каталога панели, зашифрованным (AES-256-GCM,
  парольная фраза — машинно-локальный секрет в соседнем файле с правами только для владельца);
- в `state.json`, в резервных копиях настроек и в переносе среды его нет;
- в конфигурацию CLI уходит адрес локального шлюза и заглушка вместо ключа
  (`panel-contour-no-key-needed`); настоящий ключ подставляет шлюз в момент запроса;
- в ответах панели ключ всегда маска вида «первые знаки… последние четыре».

Заголовок, в котором ключ уходит к контуру, по умолчанию `Authorization: Bearer`; пресет Azure
OpenAI сам ставит `api-key` без слова перед ключом. Шлюзу, который ждёт что-то своё, заголовок
назначается в мастере, в свёрнутом блоке «Нестандартный шлюз» под адресом; там же версия в адресе («дописать /v1, если
версии в пути нет» или «адрес как есть»), параметры каждого запроса (`api-version=…`) и
дополнительные заголовки. Это одна настройка для пробы, шлюза, эмбеддингов, агентов и картинок.
Сам ключ туда не вписывается: строка с `Authorization`, `api-key`, `x-api-key` или параметр
`key`/`token` отвергаются при сохранении с названием поля, но без значения.

Цена этого решения названа честно: **пока панель выключена, шлюз закрыт**, и направленный на него
CLI получит отказ соединения — а не тихо уйдёт в облако вендора. Это выбор в пользу предсказуемости:
корпоративный запрос, ушедший не туда, хуже любого отказа.

## Как отключить

Четыре разных действия, от самого мягкого:

1. **Снять галочку потребителя** («Настроить» → «Где работает контур») — действует со следующего
   запуска, остальные потребители остаются на контуре, файлы CLI не меняются. Если файлы этого CLI
   применены, он читает адрес контура из своей конфигурации, и вернёт его только следующий шаг.
2. **«Снять применение»** — файлы CLI возвращаются к прежним значениям, управляемый профиль
   исчезает. Контур остаётся подключённым: ассистент панели и переходник работают.
3. **«Вернуть провайдер по умолчанию»** — контур перестаёт быть активным, шлюз отвечает на его адрес
   отказом 502 «контур выключен в панели». Настройка, ключ и история расхода остаются; вернуть работу
   на него — «Сделать активным».
4. **«Удалить контур»** — просит ввести название целиком; уходят настройка, ключ и след проверки,
   применение снимается автоматически.

Копии «до» всех правок конфигураций лежат в разделе «История» и переживают удаление контура; уже
посчитанный расход тоже остаётся.

## Что панель про контур НЕ делает

- Не меняет ничего на стороне контура: ни гардрейлы, ни инструменты, ни лимиты — они настраиваются в
  админке компании.
- Не обещает возможностей, которых не проверила пробой: неподтверждённое показывается словами «не
  объявлено», а не галкой.
- Не сливает расход контура с аналитикой транскриптов: это две разные величины, и наша — оценка по
  нашему справочнику цен, помеченная знаком «≈». Шлюз, опубликовавший цену модели в самом списке
  моделей (OpenRouter), считается по этой цене; свои цены из настроек сильнее и её.

## Чего мы просим у команды платформы

Часть ограничений выше — не наш выбор, а свойство чужой платформы: панель их обходит и называет
вслух карточками «компромисс». Что именно мы просим опубликовать, чтобы эти обходы стали не нужны,
и какие вопросы у нас остались без ответа — одной страницей:
[docs/PLATFORM-ЗАПРОС.ru.md](PLATFORM-ЗАПРОС.ru.md). Ни одна строка оттуда не держит работу панели:
всё уже работает на сегодняшней платформе.
